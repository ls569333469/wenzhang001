## 一、目标与背景

将 short_article 模式的输出从"AI分析式文章"优化为"X KOL 风格的即时评论"。核心问题：开头像分析报告、缺少口语感、风格不像真人。

---

## 二、最终采纳方案（B方案）

### 架构

```
Google Sheets（半佛15,214条样本）
  ├── pattern_menu: 提取 top15 逻辑公式 → 传给策略师选
  └── random 样本 3条 → 策略师看风格感
                    2条 → 写手学语感

策略师（选题方向 + hook）
  ↓ JSON: label/angle/hook/logic_pattern/tone
写手（按方案写文）
```

| 文件 | 改动 |
|------|------|

## 三、测试历程与教训

### 教训1：改下游没用，必须改源头

| 轮次 | 改了什么 | hook 效果 |
|------|---------|----------|
| 1 | 只改写手模板（加口语化引导） | ❌ 分析式 |
| 2 | 改策略师模板（公式菜单）但没改 hook 描述 | ❌ 分析式 |
| 3 | 改策略师 hook 描述 → "不要写分析式陈述" | ✅ 口语反应式 |

**结论**：写手的开头完全由策略师的 hook 决定。hook 字段说"判断或信息" → 出来就是分析式。改成"参考样本风格，不要写分析式陈述" → 立刻变好。

### 教训2：模板渲染必须验证

策略师模板里有 `{{ rag_context }}` 占位符吗？没有！导致代码费力取了样本，但策略师的 prompt 里根本没出现。

**检查清单**：改 context 之前，必须先确认模板里有对应的 `{{ 变量 }}`。

### 教训3：字段描述 > 样本暗示

即使给策略师看了"是时候成为大肌霸了"这样的口语化开头样本，但 hook 字段描述写的是"判断或信息"，策略师依然写出分析式 hook。

**结论**：字段描述（显式指令）的影响力远大于样本（隐式暗示）。

### 教训4：思维工具会被混用

策略师模板里"思维工具"和"公式菜单"两个区块挨太近，策略师会把思维工具的词（换主体、反过来想）当成 `logic_pattern` 输出。

**修复**：在思维工具标题加"严禁作为 logic_pattern 输出"。

### 教训5：测试脚本必须严谨

- B 组说是 random 样本 → 实际调用的代码已经改成精准匹配 → 两组无区别
- 每次测试用同一篇素材 → hook 雷同，误以为模板固化
- PowerShell 输出乱码 → 应输出到文件

**检查清单**：
1. B 组必须手动构建上下文绕过代码改动
2. 每组测试必须记录完整的 system prompt + user prompt
3. 至少用 2 篇不同素材验证

## 四、Google Sheets 数据问题

### 4.1 空值行（已清理）

半佛 Tab 原有 15,269 条，其中 55 条所有字段为空（content 只有短句如"啊？"）。删除后剩 15,214 条。

### 4.2 表头行误删（已恢复）

清理空行后误删了第一行表头，导致字段映射全部失败。恢复表头后正常。

**字段映射**（`google_sheets_source.py` L36-44）：

```python
COLUMN_MAP = {
    "内容": "content",
    "博主": "author",
    "片段类型": "snippet_type",
    "情绪": "emotional_valence",
    "逻辑公式": "logic_pattern",
    "风格标签": "style",
    "父记录": "parent_record",
}
```

### 4.3 `get_samples()` style 过滤 bug（已修复）

`get_samples()` 用记录的 `style` 字段（值为"逻辑/对比"等风格标签）匹配 `"banfo"`，导致全部不匹配返回空。

**修复**：工作表本身已按风格划分（风格_半佛 = banfo），直接使用所有记录。

### 4.4 logic_pattern 标签不一致（待解决）

| 来源 | 标签格式 | 示例 |
|------|---------|------|
| 公式菜单（top15） | 粗粒度单标签 | 类比论证 |
| Google Sheets 标注 | 细粒度组合标签 | 类比论证+比喻、对比论证+生活化 |

导致精准匹配时 `logic_pattern="类比论证"` 无法匹配到 `"类比论证+比喻"` 的记录。

**后续方案**：在 `get_targeted_samples()` 中改为模糊匹配（包含即可），或在 Google Sheets 端统一标签。

### 4.5 父记录为空（未处理）

父记录字段全部为空，无法关联同一篇文章的开头/正文/结尾片段。

## 五、B vs C 方案对比结论

### B方案：Random 样本（当前采用）

**流程**：从 Google Sheets 随机取样本，不按类型或公式筛选。

```
策略师:
  1. 从 Google Sheets 随机取 3 条样本（可能是正文段落、开头金句、行动号召混着来）
  2. 样本出现在策略师 prompt 的「风格参考样本」区块
  3. 策略师参考样本的语感 + hook 字段描述（"不要写分析式"），写出 hook
  4. 从公式菜单（top15）为每版本选一个 logic_pattern

写手:
  5. 从 Google Sheets 随机取 2 条样本（3个版本共用）
  6. 照搬策略师的 hook 当开头
  7. 按 logic_pattern 组织正文
```

**示例**（IoTex 素材）：
```
策略师随机样本:
  样本1 [正文段落][对比论证+比喻]: "人生不就贵在多试错嘛..."（讲人生哲理的）
  样本2 [正文段落][时间对比]: "我再年轻5岁都会不屑一顾..."（讲感悟的）
  → 跟 IoTex 黑客话题完全无关，但 LLM 从中学到了"半佛"的语气

输出 hook: "200万美元买个教训，这IoTex也太贵了！"
输出 V2 hook: "币圈一天，人间一年。IoTex这波啊，属于是考古项目诈尸了…"
```

### C方案：精准样本匹配（备选，待标签统一后启用）

**流程**：按 snippet_type 和 logic_pattern 精准筛选样本，策略师和写手共享同一套开头金句。

```
策略师:
  1. 精准取 2 条「开头金句」+ 1 条「行动号召」样本
  2. 样本出现在策略师 prompt 的「风格参考样本」区块
  3. 策略师参考样本的语感写 hook，从公式菜单选 logic_pattern

写手（每版本独立取样本）:
  4. 取策略师看过的同一条「开头金句」（共享，保证风格一致）
  5. 按策略师选的 logic_pattern 精准取 1 条匹配的「正文段落」
     例：策略师选了"类比论证" → 取一条 logic_pattern 含"类比论证"的正文样本
  6. 写手看到的开头样本和策略师一致，正文样本和公式一致
```

**示例**（IoTex 素材）：
```
策略师精准样本:
  开头金句1 [现象洞察]: "我最近还发现一个很有趣的现象..."
  开头金句2 [悬念设问]: "微信步数藏了多少人情世故"
  行动号召1 [因果论证]: "正因为这个世界上没有一定能赢的制胜法..."

V1 写手样本（策略师选了"类比论证"）:
  开头金句: 与策略师相同 → "我最近还发现一个很有趣的现象..."（共享）
  正文段落 [类比论证]: "夜店酒水贵，又吵又闹，为什么那么多人去？"（按公式匹配）

输出 hook: "200万刀的教训，够不够买一份全链安全指南？"
输出正文: "就像一辆高速行驶的汽车，哪怕只有一个螺丝松动..."（确实用了类比）
```

---

### 对比总结

| 维度 | B（random） | C（精准） |
|------|-----------|---------|
| **策略师看什么样本** | 随机 3 条（可能全是正文段落） | 精准：2 开头金句 + 1 行动号召 |
| **写手看什么样本** | 随机 2 条，3 版本共用 | 每版本独立：1 共享开头 + 1 按公式匹配正文 |
| **策略师-写手样本一致性** | ❌ 各自独立随机 | ✅ 共享同一条开头金句 |
| **Hook 质量** | ⭐⭐⭐⭐ 靠约束兜底就够好 | ⭐⭐⭐⭐ 略好但差距不大 |
| **正文公式执行** | ⭐⭐⭐ LLM 自由发挥 | ⭐⭐⭐⭐ 有对应公式的样本参考 |
| **代码复杂度** | 低（2次取样） | 高（策略师3次+每版本2次=9次取样） |
| **数据依赖** | 不依赖标签一致性 | 高度依赖（标签不一致时退化为 random） |
| **当前问题** | 无 | logic_pattern 标签粗细不一致 |

**决策**：现阶段采用 B 方案。待 Google Sheets 的 logic_pattern 标签统一后（"类比论证+比喻" → "类比论证"），再切到 C 方案。

## 六、其他风格优化复用清单

1. **先改策略师模板的 hook 描述** — 这是效果最大的单点改动
2. **确认 `{{ rag_context }}` 在模板中渲染** — 否则样本白取
3. **运行 `get_pattern_menu()` 检查公式菜单** — 确认该风格有足够的 logic_pattern 标注
4. **检查 `get_samples()` 是否能正常返回** — 排除 style 过滤问题
5. **至少用 2 篇不同素材测试** — 避免素材本身导致 hook 雷同
6. **测试脚本记录完整 prompt** — 策略师 system/user prompt 和写手 user prompt 都要记录
7. **检查思维工具是否混入 logic_pattern** — 确认约束语生效
