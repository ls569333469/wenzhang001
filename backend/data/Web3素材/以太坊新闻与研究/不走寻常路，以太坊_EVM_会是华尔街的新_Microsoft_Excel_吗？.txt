全文如下：

本周的主题是 Circle 和 Stripe 宣布推出的“企业版 L1”（corpo-L1s）。

1. Circle 发布的新 L1 区块链 Arc 是一条兼容 EVM 的公链，由 20 个经许可的验证者组成，这些验证者来自受监管和可信赖的机构联盟。

2. Stripe 则在开发一条新的 L1 链，预计将采用 Paradigm 的 RETH 客户端 — — 一个基于 Rust 开发的高性能以太坊客户端。值得注意的是，Paradigm 创始人 Matt Huang 目前在 Stripe 的董事会任职，并很可能对这条被称为 Tempo 的 Stripe Chain 提供了重要的开发支持。

本周加密推特上的讨论几乎可以归结为一句话：这对加密货币来说是好事还是坏事？那对“你的仓位”来说又是好事还是坏事？我个人认为“许可型 L1” 极其乏味。在我看来，加密货币的价值与 “核心叙事” 在于开源软件，而以太坊正处于这个故事的中心。去构建一条“许可型 L1”，已经远离了加密的主线叙事，甚至显得毫不相关。

在 Circle 和 Stripe 的案例中，区块链技术只是被当作一种数据库结构来利用，而仅此而已。

Arc 和 Tempo 会发行 L1 资产吗？

如果会，这至少意味着它们有意愿去推动网络的去中心化，那么这些链看起来就会更接近我认为有趣的方向。但就目前而言，在缺乏进一步数据的情况下，合理的判断是，这两条链都不会发行任何 L1 资产，而只是作为私有内网，用于前端应用背后的稳定币结算。

在加密世界还有一个 “铁律”：如果一个项目有能力发行代币，那它最终一定会发行代币（对，说的就是你 Base ）。所以完全排除这种可能性其实是天真幼稚的。如果这些 “企业级 L1” 最终真的选择发行代币，那将使它们更接近一个开源、去中心化的开发者平台，而在我看来，这才更接近加密的核心叙事。

Stripe 和 Circle 会尝试吸引开发者在它们的链上进行开发吗？

如果开发者在这片 “他人土地” 上既得不到奖励，也不是这片土地的部分所有者，他们真的会愿意去建设吗？Stripe 确实已经拥有一个庞大的开发者社区……但那是 Web2 开发者社区，他们主要构建的是 Web2 前端与电商网站。

那么，这能否顺利转化为推动 Web3 开发者在 Tempo 上进行建设？在 Tempo 上构建的价值，是否真的比在以太坊或其任一 L2 上构建的价值更高？或许，这些链依旧会停留在 “惰性” 的许可型联盟链层面，没有 L1 资产，仅仅是作为业务逻辑的后端，用于替代 Visa、Mastercard 和 SWIFT，构建它们自有的结算网络。

所有这些问题目前都没有答案，也无法确定。因此，现在就去争论 “这对 BTC、ETH、SOL 或整个加密行业究竟是好是坏”，还为时过早。唯一无可争辩的事实是：这些 “企业级 L1” 链，对以太坊虚拟机（EVM）是利好。

这是我本周在 Ethereum NYC 演讲时展示的一张幻灯片：

一切始于 Robinhood Chain — — 这是第一家传统金融（TradFi）公司构建并拥有 EVM 实例的案例。Robinhood 已经雇佣了 EVM 开发者，如今，理解 EVM 已成为 Robinhood 业务的核心能力。现在，我们可以将 Circle 和 Stripe 也加入这份名单，它们同样在公司架构中引入并管理 EVM 技术人才。

重点在这里：任何进入加密领域的传统金融公司，都必须雇佣 EVM 开发者。 对于一家 TradFi 公司而言，理解 EVM 正在成为 “入场门槛”，以便将自身的后端逻辑升级到区块链未来。

正如过去 Microsoft Excel 支撑着传统金融运转，如今，以太坊虚拟机（EVM）正在成为华尔街必须配备的人才与基础设施 — — 否则它们将面临被基于以太坊的新事物颠覆，甚至失去市场份额。

当你深入“以太坊的兔子洞”后，就会意识到，所有路径最终都会回到 ETH 的价值捕获，而这正是其中之一。尽管这种方式非常间接且温和，但 EVM 帝国的扩张 最终都会为处于其核心的资产 — — ETH — — 带来价值增益。

附：什么是以太坊 EVM？

EVM（Ethereum Virtual Machine），中文叫“以太坊虚拟机”，是一个运行在以太坊区块链上的虚拟计算环境，你可以把它理解为一个运行在全球数万个节点上的“去中心化计算机”。它的作用是让任何人在以太坊上部署和执行智能合约，而不需要信任任何中心服务器。

简单来说，EVM 就是让以太坊不仅能转账，还能执行代码、运行逻辑，实现一个“全球共享的区块链操作系统”。EVM 是所有以太坊智能合约的运行环境。每当有人调用合约，EVM 就会逐条“执行”其中的代码，确保逻辑正确并记录在链上。以太坊账户、余额、合约的运行结果，都是在 EVM 中“状态变化”完成的。EVM 确保每次变化是可验证且一致的。不论你在哪个以太坊节点执行智能合约，EVM 都会给出完全相同的执行结果。这也是区块链可共识的基础。为了防止滥用资源，EVM 采用了 Gas 机制，代码执行越复杂、占用资源越多，所需的 Gas 就越高，用户需要用 ETH 来支付。

2013 年底：Vitalik Buterin 提出了以太坊白皮书，目标是创建一个通用平台，不仅能转账，还能编程。2015 年 7 月：以太坊主网正式上线，EVM 同时诞生。EVM 的设计灵感来自于“图灵机” — — 也就是说，它被设定为图灵完备，可以运行任何复杂程序，就像现实世界的电脑一样。最早版本的 EVM 是用 Solidity 写合约，用 EVM 字节码来执行。后来出现了多种编程语言（Vyper、Yul）以及多种兼容 EVM 的链（称为“EVM 兼容链”）。

开发者编写的 Solidity 智能合约会被编译成一种中间语言（EVM 字节码），EVM 就像一台虚拟 CPU 一样一条条执行这些字节码指令。EVM 使用“栈式虚拟机”结构，不同于传统内存调用的 CPU，更适合运行在资源受限的区块链节点上。EVM 是沙盒化运行的，合约之间隔离，不会影响其他节点的运行，增加了安全性。

EVM 的广泛采用，使得众多新公链（如 BNB Chain、Polygon、Avalanche C-Chain、Fantom）都选择“EVM 兼容”，因为开发者可以直接使用以太坊上的工具（如 MetaMask、Remix、Hardhat），用户可以轻松跨链使用相同的钱包与应用界面。EVM 的结构也推动了 Layer2（如 Arbitrum、Optimism）、Rollup 等扩容技术的发展。

虽然 EVM 功能强大，但也存在一些限制：性能不高（每秒交易数有限）；开发语言 Solidity 有安全隐患；字节码不易调试和优化。因此，出现了许多替代方案或扩展方案：eWASM：未来以太坊升级后可能用 WebAssembly 替代 EVM，增强性能；Move、SVM（Solana）、CosmWasm（Cosmos） 等，是其他链的虚拟机设计，不兼容 EVM。
