## Phase 4：端到端全链路测试 + 反馈回收（1-2h）

**目标**：完整模拟"每日广场内容生产"，**每条输出都做结构化评审**

### 测试场景

| # | 场景 | 输入 | 期望输出 |
|---|------|------|---------|
| 4.1 | 短帖（100-500字） | "根据今天的官推写一条短帖" | ≤500字，含标签，基于真实推文 |
| 4.2 | 长帖（500+字） | "写一篇 ROBO 项目深度分析" | 500-900字，投研+观点混合 |
| 4.3 | 去重测试 | 连续生成2条短帖 | 第2条角度不同 |
| 4.4 | Critic 拦截 | 故意输入无关内容 | Critic 给 REWRITE |

### 📋 每条输出的评审维度（数据回传）

每次生成内容后，按以下维度打分记录，**用于反哺提示词和产品优化**：

#### A. 内容质量（→ 反馈给提示词优化）

| 维度 | 打分(1-5) | 发现的问题 → 提示词改什么 |
|------|----------|------------------------|
| **事实准确性** | | 有幻觉 → 加"仅基于提供素材"硬规则 |
| **观点有没有立场** | | 太中性 → writer 加"必须有明确判断" |
| **开头吸引力** | | 平淡 → 借鉴短篇的"hook 规则" |
| **语言通俗度** | | 太专业 → 加"面向小白"约束 |
| **节奏/可读性** | | 一段到底 → 加"短句+换行"节奏规则 |
| **标签完整性** | | 缺标签 → critic 加标签检测 |

#### B. 产品缺陷（→ 反馈给代码/功能优化）

| 维度 | 发现了什么 → 改什么 |
|------|-------------------|
| **数据不够用** | 33条推文够不够？需要补新闻/白皮书？ |
| **检索不精准** | 拉到的参考资料跟主题不相关？→ 调检索逻辑 |
| **字数超标/不足** | 实际输出 vs 限制 → 调 mode_configs 或提示词 |
| **无法自选角度** | 用户想写特定角度但没法控制 → 加角度选择器 |
| **生成太慢** | 耗时多少秒？哪个 agent 最慢？→ 优化 |

#### C. 与人工基线对比

- 你手写一条同主题的广场帖子作为 **baseline**
- AI 生成的 vs 你手写的，逐条对比上述维度
- 差距最大的维度 = 最优先要改的提示词
