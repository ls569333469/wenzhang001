## 1. 架构概述

### 1.1 双引擎设计

| 引擎 | 定位 | 数据来源 | 处理方式 |
|------|------|----------|----------|
| **Web2 风格库** | 教 AI "怎么写" | 人工精选 | 手动录入 + 脚本解析 |
| **Web3 知识库** | 给 AI "写什么" | 行业资讯 | Antigravity 自动清洗 |

### 1.2 数据流

```
本地 TXT/JSON → Antigravity (LLM) → 结构化 JSON → Lark 多维表格
```

## 3. Antigravity 接入协议

### 3.1 System Prompt

```
**Role**: 你是一个 Web3 行业情报清洗专家。

**Task**: 阅读输入的文章内容，提取关键信息，并严格输出为一个标准的 JSON 对象。

**Output Requirement (Strict JSON Format)**:
{
  "title": "文章标题，不超过30字",
  "summary": "用3-5句话概括核心内容。必须包含：核心事件、关键数据、重要人名。",
  "keywords": "3-5个关键词，用英文逗号分隔",
  "info_depth": "快讯 / 资讯 / 深度",
  "fact_type": "事实 / 观点 / 黑话",
  "publish_date": "YYYY-MM-DD 或 Today"
}
```

### 3.2 字段映射

| JSON 输出 | Lark 字段 |
|-----------|-----------|
| `title` | 标题 |
| `summary` | 核心摘要 |
| `keywords` | 关键词 |
| `info_depth` | 信息深度 |
| `fact_type` | 事实类型 |
| `publish_date` | 发布日期 |
| (脚本变量) `folder_name` | 赛道分类 |
| (脚本变量) `raw_content` | 正文原文 |

## 4. 入库脚本

### 4.1 主脚本

```bash
# 单个文件夹
python -m scripts.ingest_antigravity --folder "DeFi进展与分析" --limit 10

# 所有文件夹
python -m scripts.ingest_antigravity --all --limit 50
```

### 4.2 核心功能

- ✅ MD5 去重（基于正文原文）
- ✅ LLM JSON 输出解析
- ✅ 自动清理 Markdown 标记
- ✅ 并发控制（默认 3）
- ✅ 入库前长度截断

## 5. 数据质量保障

### 5.1 Prompt 层约束

| 字段 | 约束方式 | 说明 |
|------|----------|------|
| 核心摘要 | **3-5句话** | 比字数限制更易遵守 |
| 关键词 | 3-5个 | 逗号分隔 |
| 信息深度 | 三选一 | 快讯/资讯/深度 |
| 事实类型 | 三选一 | 事实/观点/黑话 |

### 5.2 代码层兜底

```python
# 入库前强制截断
summary = structured_data.get("summary", "")
if len(summary) > 200:
    sentences = summary.split('。')
    truncated = '。'.join(sentences[:4]) + '。'
    structured_data["summary"] = truncated[:180]
```

### 5.3 常见问题处理

| 问题 | 解决方案 |
|------|----------|
| JSON 解析失败 | `response.replace('```json', '').strip()` |
| 日期显示 Today | 人工在 Lark 补录 |
| 摘要过长 | 代码层截断 |
| 赛道分类为空 | 脚本预检本地文件夹名 |

## 6. 运营 SOP

1. **归档**：将文章复制到 TXT，放入对应文件夹（如 `Layer2动态与分析`）
2. **清洗**：运行 `ingest_antigravity.py` 脚本
3. **验收**：在 Lark 检查 `核心摘要` 和 `信息深度` 是否正确
4. **入库**：将状态改为 `已入库`
