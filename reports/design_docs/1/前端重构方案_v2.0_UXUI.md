## 1. 重构目标

通过**组件化拆分**和**状态管理重构**，解决 `page.tsx` (566行+) 难以维护的问题，并提供**极简主义**的视觉体验。

## 2. UX/UI 设计方案 (Design Options)

为了实现“沉浸式写作”，我们提供三种不同的布局方案供选择。

### 方案 A: 经典三栏工作台 (The Classic Workbench)
**适用场景**: 适合需要频繁调整参数、参考上下文的重度用户。
**布局逻辑**:
- **左栏 (Sidebar)**: 固定。配置区 (Style, Narrative, References) + Lark 状态。
- **中栏 (Canvas)**: 弹性。纯净的写作画布，顶部仅显示当前阶段 (Stage)，底部显示生成进度。
- **右栏 (Inspector)**: 可折叠。Agent 执行时间轴 (Timeline) + 实时思维流 (Terminal)。
**优点**: 信息密度高，掌控感强。
**缺点**: 屏幕占用较多，沉浸感稍弱。

### 方案 B: 聚焦模式 (Focus Mode) - *推荐*
**适用场景**: 强调生成的“心流”体验，视觉中心绝对集中在内容上。
**布局逻辑**:
- **左侧 (Drawer)**: 默认收起，鼠标悬停或点击展开。存放所有配置项。
- **中央 (Main)**: 全屏宽幅画布。背景纯白/极简灰。
    - **Step 1**: 巨大的输入框 (Typeform 风格)。
    - **Step 2**: 选项卡片 (Grid 布局)。
    - **Step 3**: 文章生成流 (Typing Effect)，由于没有右栏，Agent 状态以“微件 (Widget)”形式悬浮在右上角。
- **右侧**: 无常驻栏。日志通过底部 Toast 或悬浮球呼出。
**优点**: 极致沉浸，视觉冲击力强 (Vercel/Linear 风格)。
**缺点**: 调整配置需要多一步操作。

### 方案 C: 悬浮面板 (Floating Panel)
**适用场景**: 类似 IDE 的灵活性。
**布局逻辑**:
- **底图**: 也是全屏画布。
- **面板**: 所有功能区（配置、日志、时间轴）都是可拖拽、可缩放的“悬浮窗”。
- **Dock**: 底部有一个 Dock 栏，用于开关各个面板。
**优点**: 极客范，用户自定义程度最高。
**缺点**: 实现复杂度高 (Z-index 管理)，移动端难以适配。

## 3. 架构设计 (Technical Architecture)

### 3.1 目录结构重构
将 `page.tsx` 解耦为 Feature-based 结构：

```
src/
├── app/
│   └── page.tsx                # 仅作为 Layout 容器，无业务逻辑
├── features/
│   └── workbench/
│       ├── components/
│       │   ├── WorkbenchLayout.tsx # 核心布局管理器 (根据方案 A/B/C 切换)
│       │   ├── SidebarConfig.tsx   # 左侧配置
│       │   ├── WritingCanvas.tsx   # 中央画布
│       │   ├── AgentInspector.tsx  # 右侧/悬浮监控
│       │   └── ...
│       ├── hooks/
│       │   └── useTimeline.ts      # 动画与时间轴逻辑
│       └── stores/
│           └── useWorkbenchStore.ts # Zustand 状态管理
```

### 3.2 状态管理 (Zustand)
废弃 `useState` 传参地狱，使用 Zustand 原子化状态：

```typescript
// features/workbench/stores/useWorkbenchStore.ts
import { create } from 'zustand'

interface WorkbenchState {
  // Core Data
  input: string
  mode: string
  references: string[]
  result: string
  
  // UI State
  stage: 'input' | 'analyzing' | 'selection' | 'generating' | 'finished'
  sidebarOpen: boolean
  inspectorOpen: boolean
  
  // Actions
  setInput: (txt: string) => void
  setStage: (stage: Stage) => void
  toggleSidebar: () => void
}

export const useWorkbenchStore = create<WorkbenchState>((set) => ({
  // ... implementation
}))
```

### 3.3 样式系统 (Design System)
基于 shadcn/ui + Tailwind 进行统一：
- **Color Palette**: 
    - `bg-background` (纯白/黑)
    - `bg-muted` (F8F9FA)
    - `text-primary` (slate-900)
    - `accent` (indigo-600 -> 建议改为更高级的 "Interstellar Blue" #2563EB)
- **Typography**: Inter / Geist Mono。
- **Motion**: 使用 `framer-motion` 处理面板展开/收起、卡片加载动画。

## 4. 实施路线图 (Roadmap)

1.  **Step 1: 脚手架搭建 (Infrastructure)**
    - 安装 `zustand`, `framer-motion`, `clsx`, `tailwind-merge`。
    - 建立 `features/workbench` 目录结构。

2.  **Step 2: 状态迁移 (State Migration)**
    - 将 `page.tsx` 中的 state 迁移至 `useWorkbenchStore`。
    - 验证逻辑闭环（不涉及 UI 变更）。

3.  **Step 3: 组件拆分 (Component Extraction)**
    - 拆分 `SidebarConfig`。
    - 拆分 `WritingCanvas`。
    - 拆分 `AgentInspector`。

4.  **Step 4: UI 升级 (UI Upgrade)**
    - 按照选定方案 (A/B/C) 组装组件。
    - 添加微交互动画。
