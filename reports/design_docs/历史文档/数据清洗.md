这份文档记录了我们在构建 Quantum Studio v5.2 过程中的关键决策路径。

它不仅仅是一份“会议纪要”，更是一份架构决策记录 (Architecture Decision Record, ADR)。它解释了我们是如何从一个模糊的想法，一步步推导出现有的技术方案，以及为什么要否定那些看似诱人的替代方案。

🏛️ Quantum Studio 架构演进与决策复盘 (ADR)
核心原则：低成本 (Cost-Effective)、高解耦 (Decoupled)、安全第一 (Safety First)。

1. 架构层决策：工具形态
❓ 问题：清洗数据的工具应该放在哪里？是集成在现在的写作软件（UI）里，还是单独做？

❌ 方案 A：集成在前端 Web UI 中

设想：在网页上做一个“上传清洗”按钮，点一下全自动。

被否决原因：性能瓶颈与超时。清洗 50 篇长文涉及大量 LLM 运算，会导致浏览器卡死或 HTTP 请求超时。且这属于“后台管理”低频操作，开发复杂的前端界面属于资源浪费。

✅ 方案 B：独立的后端 CLI 脚本 (cleaner_cli.py)

被采纳原因：

解耦：清洗数据（脏活累活）与生成文章（核心业务）互不干扰。

复用：直接复用后端的 .env 配置和 Python 环境。

效率：黑客风格的命令行，开发成本极低（1小时），运行稳定。

2. 核心逻辑决策：生成方法论
❓ 问题：如何让 AI 既能像“咪蒙”一样煽情，又能像“分析师”一样专业？

❌ 方案 A：简单的风格提示词 (Style Prompting)

设想：Prompt 里写“请用咪蒙的语气写一篇以太坊研报”。

被否决原因：精神分裂。AI 会用咪蒙的语气瞎编数据（幻觉），或者用枯燥的数据破坏咪蒙的节奏。风格与内容无法融合。

✅ 方案 B：壳肉分离法 (Shell-Kernel Separation)

被采纳原因：这是本项目的核心护城河。

壳 (Shell)：提取逻辑公式（如“撕破遮羞布+制造焦虑”），负责骨架和情绪。

肉 (Kernel)：提取硬核数据（如“TVL 突破 10 亿”），负责填充血肉。

效果：AI 像填空题一样，把“真数据”填进“情绪模板”里，保证了逻辑的煽动性和数据的真实性。

3. 数据层决策：素材来源与清洗
❓ 问题：如何扩充素材库？可以直接爬取媒体文章吗？

❌ 方案 A：全量爬取 (Blind Scraping)

设想：把律动、Foresight 的文章全爬下来喂给 AI。

被否决原因：信噪比灾难。Web3 媒体充斥着 PR 软文和垃圾信息。垃圾进，垃圾出（GIGO）。且存在极大的**“喊单风险”**（AI 可能会把项目方的诈骗软文当成利好去推广）。

✅ 方案 B：白名单 + 智能预判 (Whitelist & Pre-Filter)

被采纳原因：

物理隔离：将素材严格分为 Flash (快讯/肉) 和 Article (长文/逻辑)。

TTL 机制：快讯有效期仅设为 3 天，防止引用过期行情打脸。

LLM 预判：引入 LLM 对爬取内容进行评分，低于 4 分（如无实质内容的通稿）直接丢弃。

4. 技术栈决策：模型选择
❓ 问题：使用哪家公司的 AI 模型？

❌ 方案 A：绑定 Google GenAI SDK

设想：直接调用 google.genai 库。

被否决原因：厂商锁定。如果不翻墙或 Google 涨价，系统会瘫痪。且与您现有的“DeepSeek/豆包”生态不互通。

✅ 方案 B：通用 OpenAI 协议适配器 (Universal Adapter)

被采纳原因：

成本极致优化：您已配置 DeepSeek V3 (火山引擎版)，价格极低 (¥0.022)，非常适合跑大批量的清洗任务。

灵活性：代码使用 openai 标准库。只需改 .env，即可在 DeepSeek、Doubao、Gemini 之间无缝切换，无需改动代码。

5. 运营层决策：内容输出模式
❓ 问题：日更博主如何避免内容同质化？

❌ 方案 A：单一模版

设想：所有文章都用“SCQA 焦虑模型”。

被否决原因：用户疲劳。粉丝看多了焦虑文会脱敏，甚至取关。

✅ 方案 B：五行阵 + 隐形框架 (The 5-Mode Matrix)

被采纳原因：

将内容分为 5 类：行情、内幕、FUD、教程、闲聊。

每一类绑定一个特定的隐形写作框架（如教程绑定 Step-by-Step，行情绑定 PREP）。

结果：保证了输出的多样性，同时通过“程十安风格”做教程、“咪蒙风格”做情绪，实现了场景与风格的精准匹配。

🏆 最终成果总结 (The Winning Solution)
我们最终敲定的这套方案，是一个**“低代码、高智能、强风控”**的内容生产流水线：

大脑：DeepSeek V3 (低成本主力)。

手脚：cleaner_cli.py (本地命令行工具)。

记忆：Lark Base (结构化数据库)。

灵魂：Shell-Kernel (壳肉分离策略)。

# 1. 模型工厂 (LLM Factory) - 适配您的截图配置
# ==========================================

class LLMProvider:
    def __init__(self, provider_name: str):
        self.name = provider_name
        self.client = None
        self.model_name = ""

    def connect(self):
        if self.name == "doubao":
            # 适配火山引擎 (您的 DeepSeek V3 部署在这里)
            api_key = os.getenv("VOLC_API_KEY")
            # 火山引擎通常兼容 OpenAI 协议，BaseURL 如下
            base_url = "https://ark.cn-beijing.volces.com/api/v3"
            self.model_name = os.getenv("VOLC_MODEL_ENDPOINT") # 您的 ep-xxxx
            self.client = OpenAI(api_key=api_key, base_url=base_url)
            
        elif self.name == "deepseek":
            # 适配 DeepSeek 官方
            api_key = os.getenv("DEEPSEEK_API_KEY")
            base_url = "https://api.deepseek.com"
            self.model_name = "deepseek-chat"
            self.client = OpenAI(api_key=api_key, base_url=base_url)
            
        elif self.name == "gemini":
            # 适配 Gemini (OpenAI 兼容模式)
            api_key = os.getenv("GOOGLE_API_KEY")
            base_url = "https://generativelanguage.googleapis.com/v1beta/openai/"
            self.model_name = "gemini-1.5-flash"
            self.client = OpenAI(api_key=api_key, base_url=base_url)
        else:
            raise ValueError(f"不支持的模型提供商: {self.name}")

        if not self.client.api_key:
            raise ValueError(f"未找到 {self.name} 的 API Key，请检查 .env 文件")
        
        return self.client, self.model_name

# 2. 数据结构 (Schema) - 保持不变
# ==========================================

class CleanedSnippet(BaseModel):
    original_text: str = Field(description="原始片段")
    clean_text: str = Field(description="去名化后的通用内容")
    snippet_type: str = Field(description="Hook/Body/CTA/Quote/Hard_Fact")
    logic_pattern: str = Field(description="逻辑公式")
    emotional_valence: str = Field(description="High Arousal/Positive/Negative")
    quality_score: int = Field(description="评分 1-5")

class ArticleAnalysis(BaseModel):
    snippets: List[CleanedSnippet]

# ==========================================
# 3. 核心处理逻辑 (Universal Adapter)
# ==========================================

def extract_structure_from_text(text: str, author: str, provider: str) -> List[CleanedSnippet]:
    try:
        # 初始化选定的模型 (Doubao / DeepSeek / Gemini)
        llm_setup = LLMProvider(provider)
        client, model_name = llm_setup.connect()

        prompt = f"""
        你是一个专业的数据清洗专家。请阅读以下文本（作者：{author}），将其拆解为【Web3写作素材】。
        
        【清洗规则】
        1. **去名化**：将"{author}"或具体人名替换为通用代词（"我"、"老王"）。
        2. **逻辑提取**：用一句话总结`logic_pattern`（如"先抑后扬+制造焦虑"）。
        3. **格式要求**：必须返回符合 Schema 的标准 JSON。
        
        【待处理文本】
        {text[:8000]}
        """

        # 调用 LLM (使用通用的 OpenAI 接口)
        response = client.chat.completions.create(
            model=model_name,
            messages=[
                {"role": "system", "content": "You are a JSON extractor. Output valid JSON only."},
                {"role": "user", "content": prompt}
            ],
            response_format={"type": "json_object"} # 强制 JSON 模式 (DeepSeek/GPT4 支持)
        )

        # 解析结果
        content = response.choices[0].message.content
        data = json.loads(content)
        
        # 兼容性处理：有些模型返回 { "snippets": [...] }，有些直接返回 [...]
        if "snippets" in data:
            snippets_data = data["snippets"]
        else:
            snippets_data = data

        # 转换为 Pydantic 对象
        return [CleanedSnippet(**item) for item in snippets_data]

    except Exception as e:
        console.print(f"[red]LLM ({provider}) 调用失败: {e}[/red]")
        return []

@app.command()
def clean(
    folder: str = typer.Option(..., help="TXT文件夹路径"),
    author: str = typer.Option(..., help="作者名 (用于去名化)"),
    provider: str = typer.Option("doubao", help="选择模型: doubao (默认/最省钱), deepseek, gemini"),
    min_score: int = 4
):
    """
    运行清洗流水线。默认使用 Doubao (DeepSeek V3) 以节省成本。
    """
    console.print(f"[bold green]🚀 启动清洗 (Model: {provider})[/bold green]")
    
    files = [f for f in os.listdir(folder) if f.endswith(".txt")]
    
    for filename in track(files, description="Processing..."):
        with open(os.path.join(folder, filename), "r", encoding="utf-8") as f:
            text = f.read()

        snippets = extract_structure_from_text(text, author, provider)
        
        valid_count = 0
        for s in snippets:
            if s.quality_score >= min_score:
                if upload_to_lark(s, author):
                    valid_count += 1
        
        console.print(f"  ✅ {filename}: 入库 {valid_count} 条")
