## 🔴 问题 1: `style` 和 `length` 参数被后端忽略

### 问题描述
前端发送的配置参数 `style` 和 `length` 被后端完全忽略。

### 技术细节

**前端发送的请求** (HeroInput.tsx):
```typescript
config: {
    mode,         // ✅ 被使用
    style,        // ❌ 被静默丢弃
    length,       // ❌ 被静默丢弃
    temperature,  // ❌ 被静默丢弃
    knowledgeSources,
    topP,
    maxTokens
}
```

**后端请求模型定义** (main.py 第80-88行):
```python
class GenerateRequest(BaseModel):
    input: str
    mode: str                    # ✅ 只有这个被接收
    narrative_type: str
    references: List[str]
    selected_option: Optional[Dict[str, Any]]
    info_anchors: Optional[Any]
    api_config: APIConfig
    # ❌ 没有 style 字段
    # ❌ 没有 length 字段
    # ❌ 没有 temperature 字段
```

**Pydantic 行为**: 未定义的字段会被**静默丢弃**，不会报错。

### 修复建议
```python
class GenerateRequest(BaseModel):
    input: str
    mode: str
    style: str = "mimeng"      # 添加
    length: str = "medium"     # 添加
    temperature: float = 0.7   # 添加
    # ... 其他字段
```

## 🔴 问题 2: 写作风格由 `mode` 控制而非 `style`

### 问题描述
Writer Agent 使用 `mode` 参数选择风格模板，而不是预期的 `style` 参数。

### 技术细节

**writer.py 第93行**:
```python
template = MODE_TEMPLATES.get(mode, MODE_TEMPLATES["mimeng"])
#                           ↑↑↑↑
#                    使用 mode 而不是 style
```

**MODE_TEMPLATES 定义** (writer.py 第8-70行):
```python
MODE_TEMPLATES = {
    "mimeng": { "name": "咪蒙体", ... },
    "diary": { "name": "小红书赚钱博主体", ... },
    "insider": { "name": "金融内幕消息体", ... },
    "banfo": { "name": "半佛仙人体", ... },
    "xinshixiang": { "name": "新世相体", ... }
}
```

### 设计问题
- `mode` 目前既控制"创作模式"又控制"写作风格"
- UI 上分开的两个选择器其实控制的是同一个后端字段
- 用户选择 `深度分析` + `咪蒙体` 实际效果可能不是预期的组合

```
╔════════════════════════════════════════════╗

╠════════════════════════════════════════════╣
║  必须提及: {{ must_mention_str }}           ← 中文
║  关键数据: {{ key_data_str }}               ← 中文
╚════════════════════════════════════════════╝

Requirements:
1. **必须使用中文（简体）撰写全文** - This is CRITICAL.  ← 混合
2. STRICTLY follow the Strategist's outline and angle.    ← 英文
```

### strategist.jinja2 示例
```
Your task has FOUR critical parts:           ← 英文
1. Extract INFO ANCHORS from the user's source material
2. Create a content strategy plan...

**CRITICAL: VIRAL TITLE GENERATION**
Generate 3-5 title candidates using these "爆款公式" (viral formulas):  ← 混合
- 数字法则: Use specific numbers (e.g. "8000 ETH", "3个技巧")           ← 混合
- 悬念法则: Create curiosity gap (e.g. "居然...", "竟然...")           ← 混合
```

### 建议
如果目标用户是中文用户，建议将 Prompt 模板完全中文化以：
1. 提高可读性和可维护性
2. 减少 LLM 理解偏差
3. 使生成内容风格更一致

## 📊 仿写相似度评估

### 评估方法
基于素材数量、模板复杂度和 Few-Shot 学习效果推断。

### 各风格预估相似度

| 风格 | 素材数 | 模板定义 | 预估相似度 |
|------|--------|----------|------------|
| 半佛仙人体 | 832 | ✅ 有 | **80-90%** (素材丰富) |
| 咪蒙体 | 2 | ✅ 有 | **40-60%** (素材太少) |
| 新世相体 | 6 | ✅ 有 | **30-50%** (素材较少) |
| 小红书体 | 2 | ✅ 有 | **30-50%** |
| 内幕消息体 | 2 | ✅ 有 | **40-60%** |

### 影响仿写相似度的关键因素
1. **Few-Shot 样本数量**: 素材越多，模型越能学习风格特征
2. **样本质量**: 是否是该风格的典型代表作
3. **模板指令**: 风格描述是否具体且可执行
4. **LLM 能力**: 当前使用的模型是否擅长中文风格模仿

### 建议
如要提高相似度，需要：
1. 为每个风格收集至少 20-50 篇高质量样本
2. 在样本中标注风格特征（逻辑公式、句式模式等）
3. 增强 Prompt 中的风格约束指令
