## 📅 2026-01-13 更新：L4 升级 (P12.1)

### 📌 状态摘要
> **当前阶段**: P12.1 工业级清洗工具 (Phase 1 核心功能已就绪，Phase 2 待启动)

已完成 `cleaner_cli.py` v2.0 的异步化改造，实现了：
- ✅ **AsyncIO 并发**: 基于 `asyncio.Semaphore` 的并发控制
- ✅ **智能分片**: 长文本自动按段落切分 (3000字符/片)
- ✅ **断点续传**: 基于 JSON 的文件级进度记录
- ✅ **基础去重**: 运行时的本地 MD5 去重

### 🚧 待办计划 (Phase 2 - 健壮性增强)
为解决高并发下的稳定性和存量去重问题，需执行以下变更：

1.  **Lark 侧改造**:
    - [ ] `update_lark_schema.py`: 添加 `content_hash` 字段
    - [ ] `lark_client.py`: 支持 `filter` 参数以实现服务端查询
2.  **CLI 侧升级**:
    - [ ] 引入 `tenacity` 库，实现 API 限流 (429) 的指数退避重试
    - [ ] 实现 `check_exists_in_lark` 逻辑，在上传前校验 `content_hash`

### ⚠️ 风险提示
1.  **API 限流风险**: 当前版本虽支持并发，但缺乏重试机制。若并发数设为 `>1` (默认 5)，在 DeepSeek/Doubao 上极易触发 QPM 限制导致任务失败。
2.  **数据重复风险**: 当前仅支持“运行时去重”。若重启程序或多人协作，无法感知 Lark 存量数据，会导致重复上传。
