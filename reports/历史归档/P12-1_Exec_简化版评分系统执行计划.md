```jinja2
## 评审流程 (CoT链式思考)

**Step 1**: 整体结构扫描 - 观点链条是否清晰？
**Step 2**: 专业点校验 - 事实/数据/机制是否准确？
**Step 3**: 调性匹配 - 是否符合{{ style }}风格？
**Step 4**: AI痕迹检测 - 有无高频套话？
**Step 5**: 惩罚建议 - 列出扣分项

## 5维度评分 (0-10分/维)

| 维度 | 权重 | 评分要点 |
|------|------|----------|
| 1. 语义保真度/专业准确 | 35% | 事实/数据/机制是否严谨？ |
| 2. 信息价值&深度 | 25% | 有独到洞察/新角度？ |
| 3. 逻辑连贯性&结构完整 | 15% | 层层递进、无跳跃？ |
| 4. 语言流畅度&调性一致 | 15% | 匹配作者风格？无AI生硬感？ |
| 5. 原创表观度/去AI痕迹 | 10% | 无高频套话？无模板痕迹？ |

总分公式: `(分1*0.35 + 分2*0.25 + 分3*0.15 + 分4*0.15 + 分5*0.10) * 10`
```

## ⚖️ 阈值逻辑

| 分数区间 | verdict | 后续动作 |
|----------|---------|----------|
| ≥85分 | `PASS` | → Polisher |
| 70-84分 | `REFINE` | 精修，列3-5点建议 |
| <70分 | `REWRITE` | 重写 |
| revision=3 | `FORCE_PASS` | 强制通过+警告 |

## 🚨 惩罚规则 (温和版，上限45分)

| 惩罚项 | 扣分区间 | 触发条件 |

| 轻微问题 | -0~-5 | 小瑕疵，鼓励迭代 |

## 🛠️ Gemini 代码修复要点 (Critical)

### 1. `graph.py` 元组解包崩溃风险
*   **位置**: `backend/app/graph.py` (L239)
*   **问题**: `score, feedback = critic_agent(...)` 期望两个返回值
*   **修复**:
```python
result = critic_agent(...)
if isinstance(result, dict):
    score = result.get("score", 0)
    feedback = result.get("verdict", "") + ": " + "; ".join(result.get("suggestions", []))
else:
    score, feedback = result
```

### 2. Polisher 输入格式兼容性
*   **问题**: Polisher 习惯接收字符串反馈
*   **建议**: 在传递前将 JSON 转换为人类可读字符串
