## 🚨 深度排查发现的关键问题 (Critical Issues)

### 1. `graph.py` 元组解包崩溃风险
*   **位置**: `backend/app/graph.py` (L239)
*   **问题**: 代码中使用 `score, feedback = critic_agent(...)` 期望两个返回值。
*   **冲突**: 新版 `critic_agent` (P12) 返回的是一个包含完整维度的 `dict`。
*   **后果**: 运行时必报 `ValueError` 或 `TypeError`。
*   **修复**: 必须改为字典 `.get()` 方式访问。

### 2. Prompt 维度不一致 (已解决)
*   **问题**: 策略设计为 5 维度，但 Prompt 模板残留 8 维度。
*   **决策**: Claude 确认**裁剪为 5 维度**，删除无效的 "商单/时效/平台" 评分项。

### 3. Polisher 输入格式兼容性
*   **问题**: Polisher Agent 习惯接收简单的字符串反馈。
*   **风险**: Critic 现在返回复杂的 JSON 结构，直接传给 Polisher 可能导致 Prompt 污染。
*   **建议**: 在传递前将 JSON 转换为人类可读字符串（Stringify）。

## 📋 最终确定的 5 维度评分体系 (Claude 裁剪版)

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| **1. 语义保真/专业准确** | 35% | 引用准确 + 无误导 + 跟上实时共识 |
| **2. 信息价值&深度** | 25% | (原20%+5%) 原创洞察>50%，非泛泛而谈 |
| **3. 逻辑连贯&结构** | 15% | 层层递进、无跳跃 |
| **4. 语言流畅&调性** | 15% | (原10%+5%) 方差>60 + 重复率<0.35 + 符合风格 |
| **5. 原创表观度** | 10% | 方差>60 + 重复率<0.35 + **无高频套话** |

*注：原"时效性"和"平台适配"权重已整合进维度2和4。*
