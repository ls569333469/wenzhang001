# P32 投研面板 UI 增强方案

> 📅 日期：2026-03-02  
> 📌 模块：投研快报 ResearchView  
> 📄 HTML 预览：`reports/research/prompt_test/layout_enhanced.html`  
> 📄 基线还原：`reports/research/prompt_test/layout_actual.html`

---

## 1. 背景

当前投研快报页面（`/studio?mode=project_research`）的内容排列顺序是：配图 → 文案 → 报告。但实际发布工作流是**先复制文案 → 再复制配图**，布局顺序与操作顺序不匹配，导致用户需要上下来回滚动。

此外，缺少发布前的检查反馈（字数是否超限、配图是否就绪等），以及发布后效果的预览。

## 2. 设计目标

| # | 目标 | 说明 |
|---|------|------|
| 1 | **操作流匹配** | 布局顺序 = 发布操作顺序：先文案 → 后配图 |
| 2 | **发布检查** | 一眼看到配图/文案/字数/项目状态 |
| 3 | **效果预览** | 发出前看到在 X 上的真实效果 |
| 4 | **空间利用** | 配图和 X 预览并排，减少纵向滚动 |

## 3. 布局方案

### 约束条件
- 仅修改**第四栏（主内容区）**，左侧导航/配置/项目列表和右侧进度栏保持不变
- 主内容区弹性宽度，约 700-900px（取决于窗口大小）

## 4. 主推文展开机制

| 属性 | 设计 |
|------|------|
| **默认状态** | 显示前 4 行（~120字），底部渐变遮罩 |
| **展开按钮** | "▼ 展开全文 (还有 N 行)" |
| **展开后** | 全文 + "▲ 收起" |
| **复制行为** | **始终复制全文**，不管折叠状态 |
| **字符条** | 始终可见，不受折叠影响 |

## 5. 配图 & X 预览并排

- 左侧 55%：配图原图（16:9），底部「📷 复制图片」按钮
- 右侧 45%：X 风格预览卡（头像 + @handle + 推文摘要 + 配图缩略 + 操作栏）
- 响应式：主内容区 < 600px 时改为上下堆叠

## 6. 发布操作流

```
① 看检查清单确认状态
② 复制主推文（点"复制推文"按钮）
③ 下滑一格，复制配图（点"复制图片"按钮）
④ 看X预览确认发出效果
⑤ 切换到X发布
```

所有操作**从上到下**，不需要回滚。

### Phase B — Google Sheets 集成 + 项目去重（P32-B）

#### B.1 核心目标

1. **去重省资源** — 侦察官筛出的项目，48h 内分析过的自动跳过（除非有新催化剂）
2. **一个 Tab 两用** — 新建 `投研记录` Tab **替代**现有 `投研项目` Tab（后者手动维护无意义），同时服务前端项目列表展示和后端去重查询
3. **自动化** — 管道完成后自动回写记录，前端实时显示分析历史

#### B.2 Sheets 表结构（新建 Tab: `投研记录`，替代 `投研项目`）

> ⚠️ 现有 `投研项目` Tab（手动维护的 5 条种子数据）将被废弃，不再使用。

| 列名 | 类型 | 前端显示 | 后端去重 | 说明 |
|------|------|:------:|:------:|------|
| 项目名 | string | ✅ | ✅ | 唯一标识 |
| Twitter | string | ✅ | | @handle |
| 赛道 | string | ✅ | | DeFi AI / Layer2 / GameFi... |
| 上次分析时间 | datetime | ✅ | ✅ | `2026-03-03 16:00` |
| 催化剂摘要 | string | ✅ | ✅ | 上次分析时提取的催化剂 |
| 评级 | string | ✅ | | `7/10` |
| 一句话摘要 | string | ✅ | | 项目定位（从策略官报告提取） |
| 发布状态 | string | ✅ | | 已分析 / 已发布 |
| 侦察次数 | int | ✅ | | 被侦察官发现的累计次数 |

**前端读取**：`data_service.get_research_projects()` 改读 `投研记录` Tab
**后端去重**：`research_sheet.dedup_filter()` 读同一个 Tab

#### B.3 去重逻辑（时间 + 催化剂双重判断）

```
侦察官输出 N 个项目
        ↓
从 Sheets 读取 "投研记录" Tab
        ↓
遍历每个项目，判断：
        ↓
┌─── 从未分析过？─── YES → ✅ 保留（新项目）
│
├─── 上次分析 > 48h？── YES → ✅ 保留（过期了）
│
├─── 上次分析 ≤ 48h 但侦察官带了新 buzz？
│    比较 scout.buzz != sheets.催化剂摘要
│    → YES → ✅ 保留（新催化剂出现）
│    → NO  → ❌ 跳过（已覆盖）
│
└─── fallback → ❌ 跳过
```

**关键设计**：侦察官从 Twitter 抓到的 `buzz` 字段（如 "主网上线"）与 Sheets 里上次存的催化剂摘要做文本对比。如果不同，说明有新事件，即使 48h 内分析过也要重新分析。

## 9. 数据依赖与解决方案

### 检查清单数据（纯前端计算，无需改后端）

检查清单是附属功能，所有状态均从现有 API 返回数据推导：

| 检查项 | 数据来源 | 推导逻辑 |
|--------|----------|----------|
| 配图就绪 | `data.card_html` | `!= null` → ✅，否则 ❌ |
| 主推文 | `data.tweets[0]` | `.text.length > 0` → ✅ |
| 字数提示 | `data.tweets[0].char_count` | 显示实际字数，仅做展示（不做限制/拦截） |
| 项目数量 | `data.project_count` | 直接显示 |
| 总字数 | `data.tweets` | `tweets.reduce((s,t) => s + t.char_count, 0)` |

> **注意**：字符限制条仅作参考提示，不阻断发布流程。不同平台限制不同（X 280字符/中文140字），此处仅显示字数，不做强制校验。

### X 预览头像/账号（前端硬编码）

X 预览仅用于发布前的视觉确认，账号信息直接在 `XPreview.tsx` 中硬编码：

```typescript
const X_ACCOUNT = {
  displayName: '雪球88',
  handle: '@xueqiu88',
  avatarText: '雪',     // 渐变色首字头像
};
```

后续如需多账号支持（Phase C），再改为从配置读取。

### Store 更新

`useResearchStore.ts` 无需改动。新组件 `PublishStrip` 和 `XPreview` 只接收 props，不直接读写 store。数据流：

```
ResearchView (fetch data) → props → PublishStrip / XPreview / TweetCards / CardPreview
```

## 10. 边界情况处理

| 场景 | 处理方案 |
|------|----------|
| `card_html` 为 null | 检查清单显示「配图 ❌ 未生成」；配图+X预览区域显示占位提示 |
| `tweets` 为空 | 检查清单显示「推文 ❌ 无数据」；文案区显示空状态提示 |
| 主推文展开后过高 | 展开区域设 `max-height: 400px` + 内部滚动 `overflow-y: auto`，避免推走下方内容 |
| 主内容区 < 700px | 配图 + X 预览从并排改为上下堆叠（CSS `flex-wrap` 或 `@media`） |
| 配图截图（html2canvas） | 截图始终用原始 1200×675 离屏渲染，不受并排缩小的显示尺寸影响 |
| 单个项目要点复制 | 每个折叠项展开后显示独立「📋 复制」按钮 |
| X 预览推文截断 | 显示前 120 字 + "…"，底部渐变遮罩，仅作视觉模拟 |
