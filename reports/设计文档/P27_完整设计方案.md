## 二、现状问题

### 2.1 ConfigPanel 6 个无效控件

`ConfigPanel.tsx`（580 行）包含大量前端有 UI 但后端不读取的控件：

| 控件 | 后端读取 | 结论 |
|------|---------|------|
| 🌡 Temperature 滑块 | ❌ 每个 Agent 硬编码自己的 temp | 摆设 → **删除** |
| 📊 Top P 滑块 | ❌ 后端无 top_p 参数 | 摆设 → **删除** |
| 📏 Max Tokens 输入 | ❌ 各 Writer 自动计算 | 摆设 → **删除** |
| 🪝 开头吸引力 | ❌ 底层语义不匹配 | 摆设 → **删除** |
| 📐 内容保留度 | ❌ 后端无对应逻辑 | 摆设 → **删除** |
| 🧠 知识库选择 | ❌ 假数据无检索逻辑 | 摆设 → **删除** |

**结论：整个「高级设置」折叠区直接删除。**

## 五、各模式详细设计

### 5.1 🔥 锐评优化

**关键变更**: 改走完整 LangGraph 管线（策略 → 写作 → 审核 → 润色）

**优化方向**: 迁移人味化技巧、禁用词库生效、3 条候选角度差异化、锐评"公式"模板

### 5.2 🌸 吹捧模式（新增）

**定位**: 币安/CZ/何一正面解读 | **字数**: 50-500 字

**数据源**: Grok API 拉取推特动态 + 爬虫 → Google Sheet `binance_daily` Tab

**生成流程**: 用户输入话题 → 拉取最新素材 → LLM 正面解读 → 3 条候选

### 5.3 🎯 Kaito 嘴撸（新增）

**定位**: 项目方长期内容任务，量产 | **与吹捧区别**: 吹捧=走心精品，Kaito=水文量产

**数据源**: Google Sheet 按项目分 Tab（`kaito_berachain`、`kaito_monad`）

**生成流程**: 选项目 → 拉取近 N 天动态 → 找未覆盖角度 → 生成 3 条 → 避免撞角度

### 5.4 🔬 项目投研（新增）

**定位**: 新项目速览 + 投研报告 | **数据源**: Grok + Gemini（Surf API 后续）

**两层输出**: ① 一句话 Alpha ② 完整分析报告（团队/融资/代币经济学/链上数据）

### 5.5 ~~改写润色~~ → 删除

占位符模式，从未使用。涉及清理: `rewrite.py` / `rewrite.jinja2` / `rewrite.py`(API) / 前端 schema / Settings 页

### 5.6 删除「开头吸引力」控件

清理: `ConfigPanel` hook UI + `constants.ts` `HOOK_INTENSITIES` + `retention_level` 硬编码默认值
