# P30 吹捧模式设计文档

> 日期: 2026-02-24  
> 目标: 将吹捧模式（bullish_take）对齐 P29 短篇架构，实现策略师驱动的3版本内容生成

---

## 1. 背景与动机

吹捧模式原本是单版本生成，跳过策略师，直接由写手生成内容。存在以下问题：

| 问题 | 影响 |
|------|------|
| 无策略师 | 缺乏结构化选题，角度单一 |
| 无写作公式 | 内容结构随机，不可控 |
| 无风格样本 | 语感靠硬编码示例，不够灵活 |
| 单版本输出 | 无法对比选择，质量难以判断 |

P29 短篇模式已验证的成功架构：**策略师（样本+公式菜单）→ 写手（3版本循环）→ 审核 → 润色**。P30 的目标是将此架构完整复制到吹捧模式。

---

## 2. 架构对齐方案

### 2.1 数据流

```
Google Sheets（半佛积极样本，暂代刘润数据）
  ├── pattern_menu: top15 逻辑公式 → 策略师选择
  ├── random 样本 3条 → 策略师参考风格感
  └── random 样本 2条（积极情绪） → 写手学语感

策略师（praise_type + angle + hook + logic_pattern + tone）
  ↓ JSON（3个方案）
写手（按3方案分别生成3个版本）
  ↓ 合并为 draft_v1（用 --- 分隔）
审核（检查 tone / logic_pattern / praise_type 是否执行）
  ↓
润色（检测多版本格式 → 逐版本独立润色）
  ↓
最终输出（3个独立版本，可直接对比选择）
```

### 2.2 吹捧 vs 短篇对比

| 维度 | 短篇 (short_article) | 吹捧 (bullish_take) |
|------|---------------------|---------------------|
| 策略师模板 | `strategist/short_article.jinja2` | `strategist/bullish_take.jinja2` |
| 方法论 | 思维工具（换主体/换尺度/找反差） | **5条吹捧线索**（夸事不夸人/FFC法/对比夸/影响力翻译/欲扬先抑）+ **刘润4种捧法** |
| 写手角色 | 自媒体作者 | **币安合作 KOL** |
| 样本源 | banfo/mimeng 样本 | banfo 积极样本（后续换刘润） |
| 公式菜单 | ✅ pattern_menu | ✅ pattern_menu |
| 版本数 | 3 | 3 |
| 审核 | tone + logic_pattern | tone + logic_pattern + **praise_type** |

## 3. 改动文件清单

### 3.1 提示词模板

#### `strategist/bullish_take.jinja2`（重写）
- 角色：内容策划师，服务币安合作 KOL
- 思维工具：换主体/换尺度/找对比/反过来想
- 刘润4种捧法：专业型/价值型/传播型/细节型
- 输入插槽：`{{ rag_context }}`（风格样本）、`{{ pattern_menu }}`（写作公式菜单）
- 输出：JSON，含 `source_analysis` + 3个 `plans`（各含 praise_type / angle / hook / logic_pattern / tone）

#### `writer/bullish_take.jinja2`（重写）
- 角色：币安合作 KOL，持仓 BNB，有粉丝基础
- 核心原则：夸认知和决策，不夸人本身；用事实数据说话
- 风格要求：长短句交替、人味（自我修正、信息密度不均匀）
- 禁止项：AI词、低级捧词、套话收尾、公关稿用语
- 输入插槽：`{{ rag_context }}`（样本参考）

#### `critic/bullish_take.jinja2`（重写）
- 引用策略官的 `{{ tone }}`、`{{ logic_pattern }}`、`{{ praise_type }}`
- REWRITE 条件：纯转述/AI模板/低级捧词/编造事实
- REFINE 条件：捧得不到位/公式未执行/缺乏个人视角

### 3.2 后端代码

#### `strategist.py`
- 扩展 `pattern_menu` 注入范围：`short_article` → `short_article + bullish_take`
- 新增 `STYLE_OVERRIDE`：bullish_take → banfo 样本映射

#### `writer/bullish_take.py`（重写）
- 新增 `_extract_plans()`: 从策略官 JSON 提取3个方案
- 新增 `_generate_variant()`: 按单个方案生成单版本（含重试机制）
- 主函数改为循环3方案 → 生成3版本 → 返回 `variants` 列表

#### `critic/standard.py`
- 从策略官 JSON 新增提取 `praise_type`，传入审核模板

#### `graph.py`（`node_polisher`）
- 检测多版本格式（`## 版本` + `---` 分隔）
- 逐版本独立润色，保留版本结构

#### `mode_configs.py`
- `skip_strategist`: `True` → `False`
- `output_count`: `1` → `3`

## 4. 策略师 JSON 输出格式

```json
{
  "source_analysis": {
    "subject": "CZ / 一姐 / Binance / BNB Chain",
    "event": "一句话概括",
    "key_facts": ["关键事实1", "关键事实2"]
  },
  "plans": [
    {
      "label": "版本名(3-5字)",
      "praise_type": "专业型/价值型/传播型/细节型",
      "angle": "切入角度",
      "hook": "开头第一句",
      "logic_pattern": "从公式菜单选择",
      "tone": "语气"
    }
  ]
}
```

## 5. 测试结果

### 5.1 测试素材
Binance 制裁合规声明：96.8% 风险下降、97.3% 伊朗敞口减少、71000+ 执法请求、1.31亿美元没收。

### 5.2 3版本输出

| 版本 | 标题 | praise_type | 核心角度 |
|------|------|------------|---------|
| 版本1 | 数据碾压 | 价值型 | 数字冲击力，96.8%+97.3% |
| 版本2 | 流程铁律 | 专业型 | 调查→缓解→报告的执行力 |
| 版本3 | 行业标杆 | 传播型 | 公链时代谁能把敞口压缩97% |

- **Critic 评分**: 85/100 (PASS)
- **数据准确性**: 所有版本的数字锚点100%准确
- **先抑后扬**: 成功执行（"之前我也觉得合规只是应付差事…"）

### 5.3 质量评估

| 维度 | 评价 |
|------|------|
| ✅ 公式驱动 | 策略师从公式菜单选择，写手执行 |
| ✅ 样本参考 | Google Sheets 半佛积极样本注入策略师+写手 |
| ✅ 多角度 | 3种 praise_type，3种 logic_pattern |
| ✅ 数据准确 | 无编造，全部来自素材 |
| ⚠️ 公文味 | 偶有"常态化监测机制"等表述 |
