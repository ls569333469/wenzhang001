## 一、背景与目标

### 问题
当前内容生产依赖手动选题，缺乏系统化的项目发现和投研分析能力。

### 目标
构建 **自动化投研 Pipeline**：从热点项目发现到深度分析报告输出，全流程可执行。

### POC 验证结论（2026-02-25）

|--------|------|------|
| Surf API 连通性 | ✅ | `surf-1.5` / `surf-1.5-instant` 均可用 |
| 融资 / 团队数据 | ⭐⭐⭐⭐⭐ | 轮次、金额、投资方完整 |
| 社交情绪数据 | ⭐⭐⭐⭐ | Mindshare 排名、粉丝数、KOL 覆盖 |
| 估值分析 | ⭐⭐⭐⭐ | Bear/Base/Bull 三场景 |

## 二、系统架构

### 核心原则

- **Surf API 负责数据采集**（Layer 1 + 2），无需爬虫
- **本地 Python 负责清洗分级**（Layer 3），零 API 调用
- **其他 AI 负责报告写作**（Layer 4），Surf 不参与润色
- **中间数据存 JSON**，采集和写作解耦

### 数据流（4 层架构 v2）

```
┌─────────────────────────────────────────────┐
│  Layer 1: 选题发现                 [1 次调用] │
│  模型: surf-1.5 | 能力: search               │
│                                             │
│  Surf API → 搜索 @leakmealpha 推文            │
│  → 提取 + 过滤：一次性输出 Web3 项目列表        │
│  → 输出：项目名称 + Twitter + 类别 + KOL 数     │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│  Layer 2: 深度分析              [5 次调用/项] │
│  模型: surf-1.5 (reasoning=high)             │
│                                             │
│  逐项目调用 Surf，获取原始投研数据：             │
│  → 融资/团队/市场/社交/新闻/风险等全维度         │
│  → 输出：原始分析文本（含 Surf 内部标记）        │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│  Layer 3: 分级 + 清洗               [0 调用] │
│  纯本地 Python，不调 API                      │
│                                             │
│  ① 数据清洗：                                │
│     删除 Surf 内部 ID (db_internal_xxx)       │
│     删除完整 URL                              │
│     删除"待验证"无效字段                       │
│     删除分析方法论描述                          │
│  ② 自动分级：                                │
│     根据数据有无判断项目阶段                     │
│     (有融资→已融资/有代币→已上线/啥都没→概念期)   │
│  ③ 结构化输出：                               │
│     → 保存为 JSON 中间文件                     │
│     → reports/research/data_YYYYMMDD.json    │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│  Layer 4: 报告组装              [1 次调用/项] │
│  模型: Gemini / 豆包 / DeepSeek（可切换）      │
│                                             │
│  读取 JSON → 筛选关键信息 → 组装润色：          │
│  → Markdown 详细版（内部存档）                  │
│  → HTML 配图文案（推特发布）                    │
│  → 推文正文（280字内精炼版）                    │
└─────────────────────────────────────────────┘
```

### API 调用量（5 个项目）

| Layer | 调用次数 | 模型 | 说明 |
|-------|---------|------|------|
| 1 选题发现 | 1 | surf-1.5 | 搜索+过滤合并 |
| 2 深度分析 | 5 | surf-1.5 | 逐项分析 |
| 3 分级清洗 | 0 | 本地 Python | 正则清洗+自动分级 |
| 4 报告组装 | 5 | Gemini/豆包 | 逐项润色写作 |
| **合计** | **11** | - | 原 12 次→11 次，但更清晰 |

## 三、核心模块设计

### 3.1 SurfService（数据引擎）

**文件**: `backend/app/services/surf_service.py`（待创建）

```python
class SurfService:
    """Surf AI API 服务封装"""

    def call(model, query, abilities, reasoning) -> dict
    # 基础 API 调用

    def get_trending_projects() -> list[dict]
    # Layer 1: 搜索 @leakmealpha 获取热点项目（无需爬虫）

    def triage_project(name, twitter) -> dict
    # Layer 2: 快速分类定级
    # 返回: { stage, available_data[], key_events[], research_value }

    def analyze_project(name, twitter, stage, template) -> dict
    # Layer 3: 根据阶段选择模板做针对性分析

    def get_mindshare_ranking(industry=None) -> list[dict]
    # 辅助: 获取 Mindshare 排名
```

**配置项**:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `SURF_API_KEY` | `.env` | API 密钥 |
| `SURF_MODEL_QUICK` | `surf-1.5-instant` | 快速查询（选题 + 分类） |
| `SURF_MODEL_DEEP` | `surf-1.5` | 深度分析 |
| `SURF_TIMEOUT` | `300s` | 请求超时 |
| `SURF_REASONING` | `high` | 推理深度 |

### 3.2 分类定级（Layer 2）

用 `surf-1.5-instant` 快速判断每个项目，输出结构化分类：

```json
{
  "name": "Saturn Credit",
  "stage": "pre_tge",
  "available_data": ["funding", "team", "social"],
  "key_events": [
    {"type": "funding", "detail": "YZi Labs + Sora Ventures 80万"},
    {"type": "audit", "detail": "Certora 审计完成"},
    {"type": "advisor", "detail": "Pudgy Penguins 顾问加入"}
  ],
  "missing_data": ["token_price", "tvl", "onchain_metrics"],
  "research_value": "high",
  "recommended_template": "pre_tge"
}
```

**项目阶段定义**:

| 阶段 | 代号 | 判断标准 |
|------|------|---------|
| 概念期 | `concept` | 无融资、无代币、仅有白皮书或社交账号 |
| 已融资 | `funded` | 有融资轮次但无代币计划 |
| Pre-TGE | `pre_tge` | 有代币计划/预售但尚未上线交易 |
| 已上线 | `launched` | 代币已上线交易所，早期阶段 |
| 成熟协议 | `mature` | 上线超过 6 个月，有稳定的链上数据 |

### 3.3 阶段适配分析模板（Layer 3）

根据项目阶段自动选择分析重点，避免报告充满"暂无数据"：

| 阶段 | 重点分析维度 | 跳过的维度 |
|------|-------------|-----------|
| **概念期** | 团队背景、叙事热度、赛道格局、竞品对比 | 价格/TVL/链上数据 |
| **已融资** | 融资详情、团队、产品路线图、社交增长 | 代币数据/TVL |
| **Pre-TGE** | 融资、估值场景(Bear/Base/Bull)、上线概率、空投机会 | TVL/交易量 |
| **已上线** | 价格表现、流通量、交易所覆盖、短期走势、早期用户 | 长期 TVL 趋势 |
| **成熟协议** | TVL、协议收入、链上用户、竞品对比表、市场地位 | 融资历史(已公开) |

**所有阶段共有维度**：
- 📊 项目概要（定位、产品、目标市场）
- 🔥 近期催化剂（为什么被 KOL 关注）
- ⚠️ 风险评估（3-5 风险，影响×概率）
- 🎯 投资结论（看涨/中立/看跌 + 置信度 + 策略）

### 3.4 报告输出格式（双输出）

Layer 4 产出两种格式：

| 输出 | 用途 | 文件 |
|------|------|------|
| **Markdown 详细版** | 内部存档 / 深度阅读 | `reports/research/daily_research_YYYYMMDD.md` |
| **HTML 配图** | 推特封面（截图发布） | `reports/research/daily_alpha_YYYYMMDD.html` |

#### Markdown 详细版

```
# 🌊 每日投研快报
> 元信息（时间、数据源、模型）

## 📋 今日热点项目总览
| 项目 | 阶段 | 类别 | KOL热度 | 关键事件 | 投研价值 |

## 1. 项目名称
> 阶段标签 | 类别 | Twitter | KOL 热度
（阶段适配的深度分析）

## 📝 报告说明 + 免责声明
```

#### HTML 配图（推特封面）

**模板**: `reports/设计文档/P31_配图模板_v1.html`

设计要点：
- **auto-fit 网格布局**：2/3/4/6 张卡片自动适配列数 + 自动换行
- **磨砂玻璃卡片**：`backdrop-filter: blur(20px)` + 顶部渐变高亮线
- **画布弹性拉伸**：`min-height: 675px`（16:9 基准），多卡片向下延展
- **数据高亮**：`.highlight`（天蓝 #38bdf8）+ `.warning`（琥珀 #fbbf24）

自动化流程：
```
Surf API 返回分析数据
    ↓
Jinja2 模板渲染：循环注入 <div class="card"> 到 <div class="grid">
    ↓
Headless Browser 对 .canvas 截图 → PNG
    ↓
后端 API 返回图片 / 推特直接发布
```

## 七、已确认决策

| # | 问题 | ✅ 决定 | 备注 |
|---|------|--------|------|
| 1 | 每日分析几个项目 | **5 个** | 由 leak.me 数据量决定 |
| 2 | 报告语言 | **中文** | - |
| 3 | 链上数据缺口 | **先不补** | 等 Surf 迭代；只写已知数据 |
| 4 | 分析重点 | **关键事件 + 赚钱机会** | 融资/TGE/空投/资产发行等可操作信号 |
| 5 | 触发方式 | **定时任务**（目标） | Phase 1 先手动 |
| 6 | 与内容 Pipeline | **松耦合打通** | 投研数据可作为 Kaito/锐评的输入素材 |

### 打通方式

投研模块作为内容 Pipeline 的**上游数据源**：

```
投研模块产出                      内容 Pipeline 消费
──────────                      ──────────────
项目名称 + 阶段                   → Kaito Yap: 选择项目写 Yap
关键事件 + 赚钱机会               → 锐评模式: 热点事件选题
融资/团队/风险摘要               → Strategist: 作为背景素材注入 prompt
配图 HTML                        → 直接发推特（独立）
```

具体实现：投研报告生成后，结构化数据存为 JSON → 前端投研 Tab 展示 → 用户选择项目 → 一键切到 Kaito/锐评模式，自动带入项目数据。
