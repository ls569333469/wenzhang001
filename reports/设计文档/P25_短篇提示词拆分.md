# P25 短篇提示词拆分方案

> **目标**：将短篇写手的"测试全流程"提示词拆分为策略官（分析）+ 写手（执行），消除重复 LLM 调用
> **日期**：2026-02-13
> **状态**：方案制定中

---

## 1. 问题诊断

### 1.1 当前管线（6次LLM调用）

```
策略官 (strategist.jinja2, 250行通用模板)     ← LLM #1
  → 输出: 标题、事件卡片、大纲
  ↓
写手内部策略师 (_analyze_material())           ← LLM #2 ⚠️ 重复
  → 调用 strategist/short_article.jinja2 (73行)
  → 输出: 3个版本方案（六法框架）
  → 完全忽略策略官 #1 的分析结果
  ↓
写手生成 ×3                                    ← LLM #3 #4 #5
  ↓
主编评审 (critic/short_article.jinja2)         ← LLM #6
  ↓
润色 → 跳过
```

### 1.2 三个核心问题

| # | 问题 | 影响 |
|---|------|------|
| 1 | **重复分析** | 策略官分析了素材，写手又分析一遍，第二次无视第一次的结果 |
| 2 | **职责混乱** | 写手的提示词是测试环境的"全流程"版，包含了分析+选方法+写作 |
| 3 | **资源浪费** | 多一次 LLM 调用 = 多花钱 + 多等时间 |

---

## 2. 拆分方案

### 2.1 修复后管线（5次LLM调用）

```
策略官 (strategist/short_article.jinja2, 专用)  ← LLM #1
  → 分析素材 + 六法框架 + 12种写法 + 开头结尾
  → 输出: 3个版本方案
  ↓
写手 ×3 (writer/short_article.jinja2)           ← LLM #2 #3 #4
  → 按策略官方案纯写作
  ↓
主编评审                                         ← LLM #5
  ↓
润色 → 跳过
```

**关键决策**：短篇使用专用策略官模板，不走 250 行的通用模板。原因：
- 短篇不需要标题候选（直接在X上发）
- 短篇不需要爆款评分
- 通用模板任务太多，加上六法分析会超负荷

### 2.2 职责边界

| 角色 | 负责 | 不负责 |
|------|------|--------|
| **策略官** | 分析素材、选方法、选写法、分配风格 | 写文章 |
| **写手** | 按方案写作、保持人设、执行风格 | 分析素材、选方法 |
| **主编** | 评审质量、检测AI痕迹、打分 | 暂不改动（先跑一轮） |

## 3. 策略官提示词设计

### 3.1 四步分析流程

**第一步：分析原文**（4个维度）
- 结构类型：时序型 / 总分型 / 并列型
- 叙述视角：第几人称 / 专家视角 / 新闻视角
- 论证方式：演绎法 / 正向论证 / 线性思维
- 表达方式：说理文 / 论述体 / 书面语

**第二步：六法重构框架**（选2-3种）

| 方法 | 说明 | 分类 |
|------|------|------|
| 方法1 - 结构重构 | 时序→因果 / 总分→分包 / 并列→对比 | 核心（必选1-3） |
| 方法2 - 视角转换 | 换叙述主体 / 换时空维度 | 核心 |
| 方法3 - 内容重构 | 抽象↔具象（用比喻类比，不编场景）/ 换表达方式 | 核心 |
| 方法4 - 逻辑重组 | 演绎↔归纳 / 正向↔反向 | 深化 |
| 方法5 - 形式转换 | 直述→比喻 / 陈述→反问 | 打磨 |
| 方法6 - 语言优化 | 书面→口语 / 长句→短句 | 打磨 |

**第三步：匹配写法方向**（12种，3类）

#### 思考型（适合观点/趋势/商业类素材）
| 写法 | 说明 | 适合场景 |
|------|------|---------|
| 第一性原理 | 剥掉表象，找最底层逻辑 | 技术变革、商业模式 |
| 反共识 | 找主流观点的漏洞 | 热点事件、市场观点 |
| 类比迁移 | 跨行业类比解释 | 复杂概念、新技术 |
| 博弈分析 | 各方利益和动机分析 | 并购、监管、竞争 |
| 时间线倒推 | 从未来回看现在 | 趋势判断、投资逻辑 |

#### 分析型（适合数据/事件/安全类素材）
| 写法 | 说明 | 适合场景 |
|------|------|---------|
| 数据说话 | 让数字讲故事 | 链上数据、财报 |
| 因果拆解 | A→B→C因果链 | 暴涨暴跌、安全事件 |
| 对比实验 | 两个类似事物对比 | 竞品分析、历史对比 |
| 矛盾揭露 | 说的和做的不一致 | 项目方行为、监管 |

#### 表达型（适合社区/人物/争议类素材）
| 写法 | 说明 | 适合场景 |
|------|------|---------|
| 辣评定性 | 一句犀利判断给事件定性 | 争议事件、人物动态 |
| 立场对撞 | 多方立场各写一句判断 | 并购、站队、舆论分裂 |
| 设问连环 | 连续抛问题留给读者思考 | 动机不明、信息不足 |

**第四步：分配开头 + 结尾风格**

开头（5种）：
1. 冷陈述 — 最荒谬的事实平铺直叙
2. 反问切入 — 一个反问让读者自己品
3. 类比开场 — 日常类比秒懂
4. 轻描淡写 — 两个事实并列，讽刺自出
5. 随口爆料 — 像跟朋友随口说个事

结尾（3种）：
1. 说完就停 — 不总结不升华
2. 留个问题 — 悬念不答
3. 反差收束 — 轻描淡写一句事实，读者自己感受反差

### 3.2 输出格式

```json
{
  "material_analysis": {
    "structure": "时序型/总分型/并列型",
    "perspective": "专家视角/新闻视角/...",
    "core_fact": "一句话概括核心事实"
  },
  "plans": [
    {
      "label": "版本名(3-5字)",
      "methods": ["结构重构", "视角转换"],
      "writing_style": "第一性原理",
      "instruction": "针对这篇素材的具体写作指令",
      "opening_style": "冷陈述",
      "ending_style": "说完就停"
    }
  ]
}
```

**约束**：3个版本的 writing_style、opening_style 必须各不相同。

## 4. 写手提示词设计

### 4.1 保留内容
- 人设：链上老玩家、独立评论人
- 核心能力：重构（不是改写）
- 写作要求：字数 + 输出结构（判断→展开→收尾）
- 风格强制：短句、口语、密集换行

### 4.2 新增：严禁清单（含废话文学）

标点禁止：
- 破折号「——」、分号「；」

废话文学（7种）：
- 正确的废话："加密市场充满不确定性"
- 万能结尾："让我们拭目以待""时间会给出答案"
- 假装思考："这不禁让人思考""值得深思"
- 骑墙表态："机遇与挑战并存"
- 注水过渡："众所周知""事实上"
- 给读者科普常识："所谓XX，就是..."

思维禁止：
- 原文改写版/缩写版
- 新闻摘要式覆盖
- 分析师点评语气

结构禁止：
- AI模板（首先…其次…最后…）
- 总分式开头
- 一惊一乍开头
- 硬凹金句结尾

### 4.3 删除内容
- ~~第一步：分析原文~~ → 移交策略官
- ~~第二步：六法框架~~ → 移交策略官
- ~~正确示例~~ → 依赖策略官的写法指令引导风格
