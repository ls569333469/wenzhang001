## 一、背景

P34 完成了投研流水线的 LLM-first 重构（删写手/润色官、加质检官、新 prompt 体系）。
P35 解决 P34 遗留的 P2 问题，并增加两个新功能。

### 当前流水线

```
侦察官(Surf) → 策略官(Surf)×N → enrichment → 质检官 → 总结官 → 推文写手 → 配图 → 日报渲染
```

---

## 二、新功能

### F1. 重新组装日报（跳过侦察+策略） ✅ Phase 1 完成

**痛点**: 对日报项目选择不满意时，必须重跑全流程（Surf API ≈100秒/项目, ≈¥2/次）

**方案**:

```
[前端选择已分析项目] → enrichment → 质检 → 总结 → 推文 → 配图 → 日报
                       ↑ 从磁盘读已有策略官报告，跳过 Surf
```

**实际改动**:

| 文件 | 改动 |
|------|------|
| `daily_report_service.py` | 抽取 `_run_post_analysis_pipeline(projects, analysis_results, ...)` |
| `daily_report_service.py` | `load_analysis_from_disk(date, twitters, names)` — 支持 twitter + 项目名双途径匹配 |
| `research.py` | `GET /api/research/available-projects` 返回当天已分析项目 |
| `research.py` | `POST /api/research/reassemble` 接收 `selected_twitters` + `selected_names` |
| `research.py` | `ReassembleRequest` 默认 provider 改为 `volcengine` |
| `ResearchPanel.tsx` | 「🔄 重新组装」按钮移到左侧栏底部（原弹窗删除） |
| `ResearchPanel.tsx` | 发送 `selected_names` + `selected_twitters` 双字段 |
| `ResearchPanel.tsx` | localStorage 持久化侦察官搜索结果（刷新不丢） |
| `ResearchView.tsx` | 删除原有的重新组装弹窗代码 |

**边界情况**:
- 重新组装**不写入** Google Sheets（`skip_sheets_writeback=True`）
- 重新组装**不入库** ChromaDB（内容未变，避免重复条目）

---

### F2. 研报入库 + 48h 去重（Phase 2 — 未开始）

**痛点**: 项目深度报告 110 份大量重复（Yellow 连续出现 03-08、03-09），浪费 Surf API

**方案**:

```
侦察官候选列表 → 48h去重过滤 → [日志标记被过滤项目] → 策略官分析 → 入库ChromaDB
```

**存储设计**:
- Collection: `research_reports`
- ID 格式: `{twitter}_{date}`（如 `reya_xyz_20260309`），保留全部历史
- metadata: `{ project_name, twitter, date, track, catalyst, summary }`
- document: 策略官报告全文

**去重逻辑**:
- 侦察官筛选完**自动模式**候选项目后，查 ChromaDB 48h 历史
- 48h 内已分析 → 移除并日志标记 `⚠️ [dedup] Yellow 已在 03-08 分析，跳过`
- **用户手动选择的项目不受 48h 限制**（尊重用户意图）

**一次性迁移**: 现有 `reports/research/projects/` 目录的 110 份 MD 文件需要批量导入 ChromaDB

**改动清单**:

| 文件 | 改动 |
|------|------|
| `chroma_service.py` | 新增 `RESEARCH_REPORTS` collection |
| `chroma_service.py` | 新增 `add_research_report(twitter, date, content, metadata)` |
| `chroma_service.py` | 新增 `get_recent_projects(hours=48)` → 返回近48h已分析的twitter列表 |
| `chroma_service.py` | 新增 `get_project_history(twitter)` → 返回项目历史报告列表 |
| `daily_report_service.py` | 侦察后：自动模式调用 48h 过滤 |
| `daily_report_service.py` | 管线结束后：每个报告调用 `add_research_report()` |
| `research.py` | 新增 `GET /api/research/project-history?twitter=xxx` |
| 迁移脚本 | 一次性导入现有 110 份报告到 ChromaDB |
