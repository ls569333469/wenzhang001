### 架构决策

- 锐评 / 吹捧 / Kaito **保持 3 个独立模式**，各自有独立的 Writer、Prompt 模板和配置
- 底层可共用工具函数（Google Sheet 拉取、数据格式化等），但模式入口分开
- 理由：方便日后独立更新维护，避免耦合

## 1. 锐评优化

**现状**: 基本可用，目前走独立路径（不经过 LangGraph）。

**关键变更**: **改走完整 LangGraph 管线**（策略 → 写作 → 审核 → 润色），与短篇/中篇对齐。

**优化方向**:
- 迁移短篇验证过的人味化/反AI痕迹技巧
- 禁用词库 (`forbidden_patterns.yaml`) 确保生效
- 3 条候选的角度差异化
- 锐评"公式"模板（反问型、数据打脸型、类比型等）

**下一步**: 跑测试 → 确定具体问题 → 针对性优化提示词

## 2. 吹捧模式

**定位**: 针对**币安 / CZ / 何一**的正面解读。吹到心坎里，不是水文。

**字数**: 50-500 字，由目标内容决定

**核心原则**: 基于真实事件吹捧，不能瞎吹 — 需要实时素材支撑。

**数据源**:
- **推特**: 通过 Grok API（✅ 已有），拉取 @cz_binance / @heyibinance 等账号动态
- **媒体**: 复用现有爬虫，增加币安/CZ/何一关键词过滤
- 抓取结果存入 Google Sheet `binance_daily` Tab（上限 200 Tab，当前仅 3-4 个）
- 人工定期审核入库质量

**生成流程**: 用户输入话题 → 拉取 `binance_daily` 最新素材 → LLM 正面解读 → 输出 3 条候选

**Web2 吹捧风格素材库**: 暂不需要，后续按需补充

**代码架构**: 独立 Writer + Prompt 模板，走完整 LangGraph 管线

---

## 3. Kaito 嘴撸任务模式

**定位**: 针对项目方长期内容任务，每天输出不同角度的正面内容。本质是商业广告/水文。

**与吹捧区别**: 吹捧 = 走心、精品；Kaito = 水文、量产

**数据源**:
- Google Sheet 按项目分 Tab（如 `kaito_berachain`、`kaito_monad`）
- 每个 Tab 维护该项目的日常动态
- 数据来源同吹捧模式（Grok API + 爬虫）

**生成流程**:
1. 用户选择项目 → 拉取该项目近 N 天的动态数据
2. LLM 分析近期内容，找出未覆盖的角度
3. 生成 3 条不同角度的候选内容
4. 避免与历史已发内容撞角度

**前端**: 比吹捧模式多一个"选择/输入项目"的入口

## 5. 项目投研

**定位**: 新项目速览 + 投研分析报告。

**数据源**:
- **项目发现**: [leak.me](https://leak.me/)
- **投研数据**: 先用 Grok + Gemini 替代（Surf API 后续补接）
- **数据验证**: Grok API

**两层输出**:
1. **一句话 Alpha**: 快速判断（格式待调研 X 上常见格式后优化）
2. **项目分析报告**: 团队、融资、代币经济学、链上数据等

**生成流程**:
1. 用户输入项目名/合约地址
2. Grok/Gemini 获取项目信息
3. LLM 生成一句话 Alpha + 结构化分析报告
