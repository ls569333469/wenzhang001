# P25 反虚构修复方案

> **日期**：2026-02-13
> **版本**：v1.0
> **范围**：短篇（已修复）→ 锐评 / 中篇（待验证）

---

## 1. 问题发现

短篇流水线测试中，"场景还原版"输出了大量虚构内容：

| 虚构内容 | 来源 |
|---|---|
| "凌晨三点的旧金山" | ❌ 素材中不存在 |
| "Erika敲完推文最后一个词，点下发送键" | ❌ 编造动作 |
| 评论区"滑雪板换尽调清单？""几百楼" | ❌ 编造评论 |
| "四十分钟后，Bill的蓝V账号冒了出来" | ❌ 编造时间和动作 |
| "墨镜表情加一句Welcome aboard" | ❌ 编造表情细节 |

素材原文仅有2句话的事实陈述，LLM 却写出了一个完整的小说片段。

---

## 2. 根因分析

### 2.1 不是"约束不够"，是"写法本身鼓励虚构"

初始尝试：在 system prompt 和 user prompt 中加"禁止编造"约束 → **无效**。

原因：当写法指令（user prompt）和禁止约束互相矛盾时，LLM 倾向于执行写法指令。

> **结论：加约束无法对抗写法本身的虚构倾向。必须从源头替换写法。**

### 2.2 三个结构性问题

```
问题1：叙事型写法（3种）
├── 画面还原 → "用具体画面和细节还原现场" → LLM理解为"编场景"
├── 一个人的故事 → "从一个具体的人切入" → LLM理解为"编人物细节"
└── 时间线叙事 → "像讲悬疑故事" → LLM理解为"编故事"

问题2：方法3 内容重构
├── "加画面感、比喻、场景描述" → 直接鼓励编造画面
└── "补充原文没说的推断" → 直接鼓励补充不存在的内容

问题3：兜底方案 DEFAULT_PLANS
└── 第3个兜底方案使用"画面还原" → 策略官失败时也会触发虚构
```

### 2.3 虚构风险评级

| 写法类别 | 写法名称 | 虚构风险 | 说明 |
|---|---|---|---|
| **思考型** | 第一性原理 | ✅ 安全 | 纯逻辑推演 |
| | 反共识 | ✅ 安全 | 观点输出 |
| | 类比迁移 | ⚠️ 低 | 可能编不存在的类比案例 |
| | 博弈分析 | ✅ 安全 | 利益分析 |
| | 时间线倒推 | ⚠️ 低 | 推测未来，属观点 |
| **分析型** | 数据说话 | ⚠️ 中 | 素材无数据时可能编数字 |
| | 因果拆解 | ✅ 安全 | 逻辑推理 |
| | 对比实验 | ⚠️ 低 | 可能编对比对象 |
| | 矛盾揭露 | ✅ 安全 | 基于素材 |
| **~~叙事型~~** | ~~画面还原~~ | ❌ **高危** | 素材无画面时必编 |
| | ~~一个人的故事~~ | ❌ **高危** | 编人物细节 |
| | ~~时间线叙事~~ | ❌ **高危** | 编故事 |

---

## 3. 修复方案

### 3.1 替换叙事型 → 表达型

| 原来（❌ 已删除） | 替换为（✅ 零虚构风险） | 说明 |
|---|---|---|
| 画面还原 | **辣评定性** | 一句犀利判断给事件定性，像贴标签 |
| 一个人的故事 | **立场对撞** | 站多方立场各写一句判断，让读者自己选 |
| 时间线叙事 | **设问连环** | 连续抛问题不给答案，留给读者思考 |

**与六法的兼容性**：

| 新写法 | 适配六法 |
|---|---|
| 辣评定性 | 语言优化 + 内容重构 |
| 立场对撞 | 视角转换 + 逻辑重组 |
| 设问连环 | 形式转换 |

### 3.2 修正方法3 内容重构

```diff
- 抽象事实 → 具象化：加画面感、比喻、场景描述
+ 抽象事实 → 具象化：用比喻、类比让抽象概念可感知（不是编造场景）

- 补充原文没说的推断、背景、因果关系
+ 换一种表达方式呈现同一事实，不补充原文没有的信息
```

### 3.3 删除兜底方案

```diff
- DEFAULT_PLANS = [
-     {"label": "换个角度聊", "writing_style": "反共识", ...},
-     {"label": "说透本质", "writing_style": "因果拆解", ...},
-     {"label": "群里聊天", "writing_style": "画面还原", ...},  ← 虚构源头
- ]
+ # 不再有兜底方案，策略官失败时直接报错
```

### 3.4 结尾风格更新

```diff
- 画面收束 — 具体小画面或细节收束，不做评价
+ 反差收束 — 轻描淡写一句事实，让读者自己感受反差
```

## 5. 推广到其他模式的检查清单

> 以下是在 **锐评（hot_take）** 和 **中篇（mid_article）** 中排查同类问题的步骤。

### 5.1 检查项

对每个模式执行以下审计：

- [ ] **策略官模板**：是否包含叙事型写法（画面还原/一个人的故事/时间线叙事）？
- [ ] **方法3 内容重构**：是否有"加画面感""补充原文没说的"等虚构鼓励语？
- [ ] **写手模板**：严禁列表中是否有明确的反虚构条款？
- [ ] **写手代码**：user prompt 中是否有"⚠️ 严禁编造"的硬性约束？
- [ ] **兜底方案**：是否有 DEFAULT_PLANS 包含高危写法？
- [ ] **结尾风格**：是否有"画面收束"等暗示编造的风格？

### 5.2 各模式现状

| 模式 | 策略官模板 | 叙事型写法 | 方法3问题 | 反虚构约束 |
|---|---|---|---|---|
| 短篇 short_article | ✅ 已修复 | ✅ 已替换 | ✅ 已修正 | ✅ 已加入 |
| 锐评 hot_take | ⬜ 待检查 | ⬜ 待检查 | ⬜ 待检查 | ⬜ 待检查 |
| 中篇 mid_article | ⬜ 待检查 | ⬜ 待检查 | ⬜ 待检查 | ⬜ 待检查 |

### 5.3 修复原则

1. **写法层面**：消除任何暗示"编故事""补细节""还原场景"的写法
2. **方法层面**：内容重构只允许"换表达方式"，不允许"补充不存在的信息"
3. **约束层面**：反虚构条款必须出现在 user prompt 中（不能只放 system prompt）
4. **兜底层面**：不使用硬编码兜底方案，策略官失败时报错让用户重试
