## 🛠️ 方案 3: 锐评模式 (Hot Take) ⏱️2h ✨ NEW

### 问题
短素材 (< 100 字) 输入时，Writer 凑字数、质量低、评分差。

### 解决方案
自动检测短输入，切换到"锐评模式"，输出精炼的 50-150 字评论。

### 触发逻辑
```python
if len(raw_input) < 100:
    mode = "hot_take"  # 自动切换
    length = "tweet"   # 强制短篇幅
```

### 目标输出示例

**输入** (60字):
> 全网4小时爆仓3.33亿美元，多单占98%

**锐评输出** (~80字):
```
4小时血洗3.33亿，98%是多军。市场用最暴力的方式教你：

1. 别和趋势对着干
2. 别把杠杆当能力
3. 爆仓不会提前通知

还在扛单的朋友，今天的数据就是明天的你。🔥
```

### 实现步骤

| 步骤 | 任务 | 预估 |
|------|------|:----:|
| 3.1 | 创建 `hot_take.jinja2` Prompt 模板 | 30min |
| 3.2 | 更新 `graph.py` 添加模式判断 | 20min |
| 3.3 | 更新 `writer.py` 支持 hot_take 模式 | 30min |
| 3.4 | 前端添加 "锐评" 快捷按钮 (可选) | 20min |
| 3.5 | 测试验证 | 20min |

### 效果
- 短输入 → 不再凑字数
- 锐评风格 → 一针见血、适合 X/Twitter
- 跳过复杂流程 → Strategist 直接到 Writer

## 🛠️ 方案 7: 修复 Router 阈值 Bug ⏱️10min 🔴 CRITICAL

### 问题
Router 阈值 (< 90) 与 Critic PASS 阈值 (≥ 85) 不一致，导致 88 分 PASS 后仍被打回重写。

### 现象
```
23:33:56 - 88分 (PASS) ✅ → 但 Router 判定 < 90 → 打回 Writer ❌
23:35:20 - 80分 (REFINE) → 又要重写
23:37:02 - 85.5分 (PASS) → 终于通过
```

### 修复

```python
# graph.py 第 311 行
def router_logic(state: AgentState):
    # 修复: 把 90 改成 85 (与 Critic PASS 阈值一致)
    if state.get("critique_score", 0) < 85 and state.get("revision_count", 0) < 3:
        return "writer"
    return "polisher"
```

> **状态**: ✅ 审核通过 (可执行)

### 核心思路

**Writer 独立 + Critic/Polisher 参数化**
- 每个模式有独立的 Writer 文件 → 内容差异化
- Critic/Polisher 统一入口 + 配置驱动 → 维护成本低

### 📂 文件结构

```

├── shared/
│   ├── base_critic.jinja2       # 基础评审 (参数化)

├── writer/
│   ├── hot_take.jinja2          # 锐评专用

│   ├── deep_analysis.jinja2     # 深度专用
```
