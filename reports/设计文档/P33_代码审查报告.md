## 🔴 严重问题（上线前必须修复）

### S2: 无 .gitignore 文件
- **现状**: 项目根目录没有 `.gitignore`
- **风险**: `config/user_config.json`（含 API Key）和 `google_service_account.json`（含 GCP 凭证）可能被提交到 Git
- **文件**: `backend/config/user_config.json`, `backend/config/google_service_account.json`
- **建议**: 创建 `.gitignore`，排除 `.env`, `config/*.json`, `venv/`, `__pycache__/`, `node_modules/`

### D1: 大量 print() 调试语句（57+ 处）
- **现状**: 后端 `app/` 目录下有 57+ 处 `print()` 调用
- **重灾区**:
  - `material_sheet.py` — 11 处
  - `google_sheets_source.py` — 16 处
  - `chaincatcher.py` — 18 处
  - `main.py` — 多处
  - `llm.py` — `[LLM DEBUG]` print 4 处
- **风险**: 生产环境日志混乱，敏感信息可能泄露到 stdout
- **建议**: 全部替换为 `logger.info/debug/warning`

### P5: 无 requirements.txt
- **现状**: `backend/` 根目录缺少 `requirements.txt`
- **风险**: VPS 上无法安装依赖，部署失败
- **建议**: 本地执行 `pip freeze > requirements.txt`

## 🟡 中等问题（建议上线前修复）

### S3: CORS 仅允许 localhost
- **现状**: `main.py` L47 只允许 `localhost:3000/3001/3003`
- **影响**: VPS 部署后前端无法调用 API
- **建议**: 添加 VPS IP 或域名到 `allow_origins`

### S4: API 无鉴权
- **现状**: 所有 `/api/*` 端点无 Token/密码保护
- **影响**: VPS 公网暴露后，任何人可调用 API（包括执行管道、读取配置）
- **建议**: 至少用 Nginx Basic Auth 或加一个简单 Token 验证

### E1-补充: SSL 校验关闭
- **现状**: `surf_service.py` L75 使用 `verify=False`
- **另外**: `scripts/` 下 2 个脚本也有相同问题
- **影响**: 中间人攻击风险（低，因为 Surf API 是 HTTPS）
- **建议**: 生产环境建议改为 `verify=True`

### D3: 41 个脚本堆积
- **现状**: `backend/scripts/` 有 41 个文件，绝大部分是一次性测试脚本
- **举例**: `test_card.py`, `test_enrich.py`, `test_layer1_10day.py`, `test_surf_leakme.py` 等
- **建议**: 保留 `setup_*.py` 和 `test_full_pipeline.py`，其余移到 `scripts/archive/`

### P3-补充: main.py 巨型单文件
- **现状**: `main.py` 有 **1030 行、54 个函数/类**
- **内容混杂**: API 路由、Pydantic 模型、ingest 逻辑、素材管理、agent 配置全在一个文件
- **含废弃代码**: `generate_hot_take()` 标注 `@deprecated P27`
- **建议**: 长期应拆分为 `api/generation.py`, `api/ingest.py`, `api/config.py` 等

### R2: 报告文件无限增长
- **现状**: `reports/research/` 当前 0.5MB（低），但每日管道会持续新增文件
- **建议**: 上线后加定期清理（保留 30 天）或 logrotate
