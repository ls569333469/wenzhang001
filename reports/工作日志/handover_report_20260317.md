## 🔍 问题诊断结论

经过昨晚到今早的深度排查，我们发现系统抓取不到早期 Alpha 项目并不仅是运气问题，而是代码中存在一条**“阻击早期项目的连环过滤流水线”**，再加上 **Grok 自身的幻觉与过度洁癖**。这两个层面的叠加导致了 valid 数据被悄无声息地抛弃。

当前，这 5 个核心漏洞已被全部定点爆破，数据流已彻底打通。

## 🛠️ 修复的 5 大核心 Bug 清单

### Bug 1: 解析层“无推特连坐误杀” (代码层，已修复)
* **病因**：许多极早期的概念项目根本没有 Twitter 账号。`scout.py` 在解析表格时，对没有推特账号的极早期项目，统一赋值为 `@-`。但由于代码中的去重 `seen` 机制**仅使用 Twitter 作为唯一键**，导致第一行 `@-` 被加入集合后，后续所有独立但同样没有推特的新项目全被当作“重复数据”抛弃。
* **修复**：修改唯一键逻辑，当发现 Twitter 为 `@-` 时，退化采用“项目名称 (Name)”来进行验证去重。确保每个无推特的早期 Alpha 独立存活。

### Bug 2: 向量库 48h 历史的“群体秒杀” (数据层，已修复)
* **病因**：在 `daily_report_service.py` 中，执行 ChromaDB 向量库去重时依然只看 Twitter。如果前几天的库里碰巧存过任何一个没有推特的项目（记录为 `@-`），今天新跑出来的所有没推特的项目在对比时，都会被当作“近48小时已分析过”而直接跳过落库。
* **修复**：加入了空推特特例放行规则：`if twitter not in recent_handles or twitter in ("", "-")`。对于没有明确社交账号的早期概念，不再做强行关联。

### Bug 3: Markdown 表格“加粗语法”解析不可见 (代码层，已修复)
* **病因**：Grok 偶尔会“自作聪颖”地用 `**| 项目名称 |...|**` 的加粗形式输出表头。而原来的正则扫描器死板地要求行首必须是纯正的 `|`，遇到 `**` 直接判定表格结束，直接抛弃后续所有行（解析出 0 个项目）。
* **修复**：为 `scout.py` 重写了防弹 Markdown 提取器。现已支持全自动剥离行首/行尾的 `*` 字符和空格，且能智能跳过异常的 `|---|` 分隔行。

### Bug 4: 移除了主观“催化剂打分”拦截 (业务层，已修复)
* **病因**：代码里写死了 `if cat_score < 4 强制清空字段或跳过`，这导致大量仅仅被提到、还未发币或无实质进展的极早期项目直接被静默过滤。
* **修复**：删除了分数拦截逻辑。现在的策略是“宁可错杀一千文字，不放过一个 Alpha名称”，只要在推特列表中被提及的统统纳入 Daily Report 供阅览。

### Bug 5: 终极 BOSS：Grok 的 AI 幻觉与质量洁癖 (Prompt 层，今早修复)
* **病因**：虽然我重写了 System Prompt 命令其必须输出表格，但注入的 **Jinja2 用户提示词 (scout.jinja2)** 中还残留着诸如“排除空气和纯 Meme、只找高质量早期Alpha”的严格要求。这种拉扯导致 Grok 在反复测试中触发了“推文质量过低”的保护机制，直接回答：“没有搜索到任何符合要求的推文，无法生成表格。”
* **修复（致胜一击）**：在 `daily_report_service.py` 的 fallback 逻辑被触发时，**硬编码强行覆写了原有的 user_prompt**。现在的降级指令极其粗暴：“提取推文中提到的所有实体，不用管是不是优质项目！全部放进表格里！”同时把 `temperature` 调高到了 0.8，打破了缓存复读机。
