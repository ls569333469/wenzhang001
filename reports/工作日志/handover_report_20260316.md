# 🚀 工作交接报告：Grok API 侦察管线修复与调优

**目标**: 修复前端触发 Daily Report 时，Grok Scout 阶段频繁返回 0 个潜力项目（特别是漏掉早期 Alpha 项目）的严重 Bug。

## 🔍 问题诊断结论

在整晚的排查中，我深入到了代码的每一个层级，发现了**一条阻击早期 Alpha 项目的“连环流水线”**。
系统抓不到 `@tplr_ai` (Templar)、`iri` 等项目的根本原因，不仅是因为 Grok 的认知问题，而是我们的 **Python 解析层和去重层存在严重漏洞**，将模型真正找出的数据抛弃了。

## 🛠️ 今日修复的 4 大核心 Bug

### 1. 过滤算法的“无推特连坐”Bug（严重级）
* **病因**：`scout.py` 在解析表格时，对没有推特账号的极早期项目，统一赋值为 `@-`。但由于去重 `seen` 机制**仅使用 Twitter 作为唯一键**，导致它把第一行 `@-` 保留后，把后面所有没有推特的独立新项目全当成了“重复数据”抛弃。
* **修复**：修改唯一键逻辑，当发现 Twitter 为 `@-` 时，退化使用“项目名称 (Name)”来进行去重。现在无推特的早期 Alpha 能够顺利存活。

### 2. 48h ChromaDB 向量库的“群体秒杀”Bug（严重级）
* **病因**：在 `daily_report_service.py` 中，执行向量库去重时依然只看 Twitter。如果前几天的库里存过任何一个没有推特的项目（`@-`），今天所有没推特的新项目在对比时，都会被当作“近48小时已分析过”而直接跳过。
* **修复**：加入了空推特特例过滤规则：`if twitter not in recent_handles or twitter in ("", "-")`。对于没有明确社交账号的早期概念，不再做强行关联。

### 3. Markdown 表格的“加粗语法”解析崩溃（高优级）
* **病因**：随着系统提词强度的提升，Grok 开始用 `**| 项目名称 |...|**` 的加粗形式输出表头。而原来的日志解析正则强制要求开头必须是纯正的 `|`，遇到 `**` 直接判定表格结束，导致一整张 15 个项目的表格提取出来是 0。
* **修复**：为 `scout.py` 编写了防弹 Markdown 提取器。现已支持全自动剥离行首/行尾的 `*` 符号，且能智能跳过不规则的 `|---|` 分隔行。

### 4. Grok 自身的过度洁癖与 AI 幻觉（逻辑级）
* **病因**：旧版 Prompt 中包含“排除个人 KOL”，导致系统看到 leakmealpha 的推文就拒收；同时当项目不全是 Tier 1 时，Grok 会擅自决定写一篇小长文狡辩为什么不输出表格。
* **修复**：重写了 Grok Fallback System Prompt，加入了极强硬的规则指令（“你是无情的提取机器，绝对强制输出表格”），剥夺了它判断“项目潜力质量”的权力，强制其格式化吐出数据。
